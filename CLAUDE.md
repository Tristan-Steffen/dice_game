# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Fumble** — a Balatro-like 3D dice roguelike built in **Godot 4.7** (`gl_compatibility` renderer, Jolt physics). Code comments and in-game text are in **German**; identifiers are a mix. The whole game plays on a single table surface at world **Y = 0**, viewed as a "casino table screen": 2D UI is rendered into a `SubViewport` and displayed on a mesh (see Architecture). The table has **no edge**: the felt runs on as an endless floor that fades into the dark room (`TableGround`), leaving space for future features around the play area.

**Comments:** keep them to the necessary minimum — short German one-liners that state a non-obvious rule, constraint, or design decision. Don't restate what the code already says, don't duplicate a `description` string that sits one line below, and don't write essay-length narrative blocks or "siehe X" cross-reference chains. When in doubt, cut it.

## Architecture

### Layered `scripts/` — the folder IS the dependency rule
`core/` and `data/` must not import from folders below them. New scripts are placed by layer, not by feature:

- **`data/`** — `Resource` records only: `DieDefinition` (per-die faces/materials/runes + the innate `essence_id`), `Charm`, `Engraving`, `Pack` (sealed shop goods — Gravuren only, a die is never a pack; also home of the Magazin taxonomy — `SHELF_ORDER`/`shelf_of`/`pack_belongs`, four shelves since the Würfel-Fach went —, of `pack_uid`, the identity `GameRun._stash_pack` stamps on entry into `owned_packs`, of the three **Paketgrößen** `TIER_NORMAL/GROSS/KOLOSSAL` with their names, price factors and shelf weights, and of the four **Katalysatoren** (`CATALYSTS`, `catalyst(id)`) plus the one weight table of the Sonderposten-Wurf (`SPECIAL_ROLL_WEIGHTS`)), `DieMaterial`, `Essence`, `Rune`, `RoundEvent` (per-block round events). Each type's ids are `const` string constants (single source of truth) so a typo is a compile error, not a silent no-op that never matches in a `match`. The layer rule bites here: `Rune.tint` **mirrors the `CasinoStyle.CHARGE` literal** instead of importing it (data/ never reaches into ui/), and a test asserts the two stay equal so drift fails loudly.
- **`core/`** — pure logic, **no Nodes** (all `RefCounted`/static): `DiceScoring` (Balatro-style hand values = base points × multiplier), `CharmEffects`/`EtchingEffects`/`MaterialEffects`/`EssenceEffects`/`RuneEffects` (id-dispatched effect resolution), `GameRun` (the persistent run state — money, 30-die pool, charms, engravings, sealed packs (`owned_packs` — array order IS the player's Magazin order: `reorder_packs` moves-not-swaps like `reorder_pool`, `tidy_packs` sorts by `Pack.SHELF_ORDER`/content/uid, and the Magazin cap is **measured, not authored** — `PackDrawerView.capacity_for` counts how many full-size cassettes the strip holds, `scene_root` injects it through `set_pack_capacity` (the `apron_bottom` pattern; `PACK_CAPACITY` (20) survives only as the headless/test fallback), and it is **hard for everything**: `_stash_pack` refuses at the cap, every purchase checks before paying, and a grant that finds no place fizzles to `PACK_FIZZLE_MONEY` ($3) instead of vanishing), round progress; owns all economy methods and emits signals to the UI. Charms are hard-capped at `CHARM_CAPACITY` (6, the table's `CharmRowView.SPOT_COUNT`): `_grant_charm` refuses when `charms_full()`, `purchase_charm` therefore checks **before** paying, and the shop/Schwarzmarkt charm cards lock themselves instead of queueing an invisible seventh charm), `ScoreBreakdown`, `SlotMachine` (the Fumble-Automaten: a 5×9 symbol wall whose runs of 3+ pay sealed goods. A Gravur-Reihe's **length decides both the count and the Paketgröße**, and that ladder is `PACK_LADDER` — 3 → 1 Standard, 4 → 2 Standard, 5 → 1 Groß, 6 → 2 Groß, and from `KOLOSSAL_FROM` (7) it continues kolossal by derivation, 7 → 1, 8 → 2, 9 → 3 (`TOTAL_COLS` is the ceiling). The ladder is **uniform across the three engraving sorts** — the old per-sort yield split (Zahlen `length−2`, Material/Würfel-Gravur `length−3`) is gone, because the scarcity already lives in `_symbol_table`'s weights: a rare sort's run is *rarer*, and paying it less on top double-counted that. The run's symbol still decides WHICH sort is minted. `pack_payout(length)` is the one read of the table, the spec dict carries `tier` next to `count`, `SlotPrize.from_spec` mints through `Pack.tiered` (so name decoration and price scaling come free) and `pot_summary()["packs"]` groups the pot by sort **and** size so the display can name it — the old flat `engravings`/`materials`/`edges` counts stay for every caller that only wants a number. One deliberate dent: 6 (2× Groß = 6 base pieces) out-yields 7 (1× Kolossal = 5), because the 7 buys that back in Magazin slots — a test nails it so it stays a decision), `SideBet` (the Nebenwetten catalog: every template carries an `unlock` hub level, so the shelf grows with the casino — `roll_offers(count, hub_level, benchmark)` filters the pool *before* shuffling. Point targets are not authored, they are **scaled**: a `target_factor` times the **stored** `run.round_goal`, rounded by `_nice_target` and **frozen into the offer** at roll time — deliberately not `effective_goal()`, so a benchmark clause signed after the betting window can never move a number already printed on a button. Two stake kinds cost **nothing at placement** and bill per taken hand/die instead (`MONEY_PER_HAND`/`MONEY_PER_DIE`, collected by `GameRun.tax_side_bets` next to the clause fee in the take); if the money no longer covers the bill the bet is `voided` — it stops taxing and loses, which is the whole risk of a tax bet. The Quotenbonus factor doubles money, engravings and ⚡ but never a unique good (Sonderposten, Paket, Chipstufe, **Press-Schub**). `Payout.PRESS_BOOST` is that last one: the Nebenwette **Kettenreaktion** (hub `UNLOCK_BASE`, $8 on a Große Straße — a straight IS a chain) pays no stock at all but `GameRun.grant_press_boost()`, a one-shot `press_boost_pending` that the NEXT pressing consumes (Limit +2, Chance +25 %, `PhantomPress.BOOST_CAP`/`BOOST_CHANCE` — they live there so the button and the query read one source and core/ does not reference itself in a circle). Its `reward_label` prints the whole prize, because a boost nobody can read is not an offer. An offer the wallet cannot cover shows it: the Setzen button tints `CasinoStyle.RED` — the shop's `price_tint` grammar — via `SideBetPanel._sync_affordability`, re-asked while the window is open through `scene_root._refresh_side_bet_affordability` on money/pack/⚡ changes; the two tax stakes cost nothing at placement and never tint), `DiceOffer` (dice templates + refinement rolls; also `roll_reward_die`, the ONE souled-die roll every Prämie uses), `GameSettings` (volume/fullscreen in `user://settings.cfg` — the view reports changes, `scene_root` applies and saves them).
- **`dice/`** — the physical die: `DiceController` (physics of the 6 dice slots — throw/hold/rest-detection; which value shows comes from each slot's `DieDefinition`, physics only reports which physical face is up), `DieBuilder` (builds dice entirely in code — no `.tscn`), `DieFaceDisplay` (also owns the **pointing** at a die: `pick_face`/`edge_distance` project the face and edge midpoints to the screen and take the nearest facing one — no physics ray, because the ceremony dice carry no collision shape), `StasisEmitter` (puck + iris + beam under a floating die; the trays hang one under every slot), `FloatingDie` (a real die hovering in such a field — see *A die is never shown twice*).
- **`table/`** — 3D props, camera, and the on-table screen system (see below). `VitrineView` is one shop bay — the AUSLAGE under a shop window, in which the goods stand **on** the table surface: it solves the spots, seats the bodies, answers the pick, and drives every arrival and departure through that surface (two instances, shop and Schwarzmarkt; see *Die VITRINE*). `AusgabefachView` is the open tray right of the workbench window where the bought dice lie (see *Das AUSGABEFACH*). `PackPitView` is the table's one PERMANENT hole: the Magazin-Grube under the workbench apron — four walls, a floor, the collar over the cut edge and the light seam under it, in Archiv-Auskleidung (see *Die Data-Cells*). `LiftShaftView` is the transient one: the SCHACHT of a Hebebühne, open only while an Auslage is coming up — four walls whose back one is a mere lintel over the Öffnungsband, a collar, a light seam, a dark Hohlraum behind the mouth where the goods wait, and a movable PLATTFORM as its floor (see *Die ZWEI ANKUNFTS-GRADE*).
- **`ui/`** — 2D panels and styling shown inside the table screen (`ShopController`, `TitleView` (title screen + pause menu), `WorkshopView` — the Werkstatt bench: das Magazin, die Presse, die inline Platzierung, das Dossier und der Tausch-Wähler —, `PackDrawerView`/`PressNetView`/`PressPortalView` (das Magazin, the interactive clamp nets & the reader portals, see below), `SlotBankView`, `SideBetPanel`, `CharmLibraryView`, `EngravingRenderer`, `VitrineAnnotationView` (the ONE labelling card over a Vitrine — the Schwarzmarkt's, hanging in its window above the bay strip), `CasinoStyle`, plus the shared builders `DiceRowView`/`CharmThumb`/`DiceGridView`/`DieNetView` — the last one is the "Würfelnetz" (unfolded-cross die dossier: cell color = face material, cell border = the essence glow, gold frame = face up, plus an Essenz-Chip — a tinted diamond in the empty top-left cross corner reporting the die's soul — and per rune its glyph in an anchor cell) shown in the pit's compact net card via `TableScreen.set_pit_die`; hovering a face/edge writes a single-line material caption to a separate wide bar lower in the pit screen — between the net card and the pit's bottom wall (`set_pit_net_hint`/`place_pit_net_hint`), never inside the card). That caption has ONE source, `DieNetView.hint_for(def, face)` (material + Veredelung, Pointer, Runen; the Essenz-Chip explains the soul) — the pack nets on the workbench write the same line onto the bench's hover card, so a cell says the same thing wherever it is shown. Hovering the **die itself** (pit or queue) fills that same bar with the soul line straight away, and it is literally the Essenz-Chip's own text (`hint_for(def, DieNetView.EDGE)`, cached in `scene_root._net_essence_hint` because `_show_pit_net` runs per frame and `Essence.by_id` builds the whole catalog); a soulless die leaves the bar empty, and moving onto the card lets the cell hints take over as before. **The net is the one way a die is ever shown flat** — pit card, the workbench's 30-die grid (`DiceGridView` detail tiles) and the placement nets (`PressNetView`) all draw the same cross, because only a layout by *physical* face position can carry the Pointer arrows. `PressNetView` composes its own interactive chips into it via `cell_position`/`edge_chip`/`rune_glyphs`/`level_badges`/`pointer_arrows` instead of calling `build`, so selection, dimming and preview survive; `DiceGridView.detail_tile_size` derives the tile from `net_size`, never a guessed constant. The eye total lives **inside** the net (`total_badge`, in the free top-right cross corner opposite the Essenz-Chip) rather than on a band above it — the 30 tiles share a fixed area, so a reclaimed strip becomes bigger cells. Consequence for the placement nets: chips sit by physical index, so the by-value `face_order` no longer decides layout — it only decides build order.

### `scene_root.gd` — the single coordinator
Top-level `Node3D` (not in a subfolder). Owns exactly one `GameRun`, wires its signals to the UI, drives round flow (throw → score → take/reroll → round-goal → shop — and the **pit is the shop's second exit**: focusing it while `phase == SHOP` means "Fertig", so `_on_camera_mode_changed` calls `ShopController.close()` and `_on_shop_closed` only zooms back to the overview when the camera really stands in the hub, never yanking back a flight already under way), and passes the same `GameRun` instance (typed) to `ShopController` and `WorkshopView`, which mutate state **only** through `GameRun` methods. It also does mouse-forwarding: `_forward_screen_mouse` projects window clicks onto the table plane and `push_input`s them into the `SubViewport` (the projection is camera-independent and runs in every pose, the free camera included); `_screen_forwards_pixel` asks which VISIBLE window owns the pixel — see *Sichtbar heißt bedienbar*. `_ready` is split into named setup steps (`_setup_dice`/`_setup_table_screen`/`_setup_camera_targets`/`_setup_panels`/`_setup_settings_ui`); camera raycasts go through the shared `_ray_pick(pos, mask)` helper and click zones through `_add_click_zone`.

### The table-as-screen display system (`table/`)
- **`TableScreen`** (`table_screen.gd`) — a `SubViewport` rendering 2D UI to a `ViewportTexture` on the "Screen" mesh. Its windows live inside it: `HubView` (home page + `ShopController` as an attached page), `WorkshopView`, `SlotBankView`, `SideBetPanel`, `TreasureChestView`.
- **The title HUD** — `TitleView` is a hub page like the shop and carries the start screen, the pause menu **and the game-over screen** (`Card.GAME_OVER`; `_home_card` is where `go_back()` lands, so after a loss the way back ends at the result, not at the menu). `CameraRig.Mode.TITLE` frames it: straight down (`TITLE_BASIS`, no tilt) at the distance that fits the whole hub window plus a margin (`title_distance`, `TITLE_MARGIN`), so the table stays visible around the menu — deliberately not a cover crop. Reflections are switched off there (`ScreenReflection.set_enabled`) — mirrored dice ghosted over the menu. Page changes at the title go through `HubView.fade_page_in/out/fade_current_in` (fade out, then the page rule hands the surface over, then fade in) — a hard cut showed while the camera was still travelling. "Neues Spiel" passes `fade_page_out` an `on_hidden` callback and takes over the fade-in itself: rebuilding the run costs ~0.24 s of frame time, and it has to sit in the dark moment between the two fades, never inside a fade or under the pull-back. Boot runs the normal setup and starts the round, then opens the title over it; "Neues Spiel" resets and plays `reveal_table()` (the long pull-back). Escape/the hub's Menü entry toggles it (`_toggle_title`) and it stays put on the start screen.
- **Combo chips** — every combination stands as a physical 3D chip on the **felt** (`ComboChipView`, model `assets/models/chip.glb`), wired into the LED network at its pins; there is no window under them. In `socket_mode` the 2D `ComboCellView` draws **nothing at all** — it survives purely as the data record and pixel anchor (cell center = origin of the scoring comets, cell size = basis of the wiring geometry). `ComboChipView.pin_offsets_px` is the single source for where the pins sit in screen pixels — everything docking onto them (the LED stubs, the purchase comets) derives from it instead of re-deriving the projection. The chip's **lid carries the display**: name, Basispunkte, ×Mult and the level badge ("LVL n", gold from `ComboCellView.GOLD_LEVEL`) sit as Label3Ds flat on a glass field, because the lid is the face the overview camera sees best. The chip glows in **one fixed operating tone** (`BAND_COLOR`/`BAND_ENERGY`) — the level is carried by the LVL badge alone, never by colour; the old heat ramp is gone, so band colour is free for the three *states* below. The lid glass stays deliberately dark and capped (`SCREEN_EMISSION_MAX`) so the text never washes out. **Upgrading happens at the chip, and the lid is the whole interface** — there is no tag beside it and deliberately no hover window: hovering (`set_upgrade_hover`) switches the score line to the values **after** the purchase in `DieFaceDisplay.PREVIEW_NUMBER_COLOR` (green = "does not stand that way yet", the same green as the workbench preview) and fades in the ⚡ price to the **left of the LVL badge**; nothing of the offer shows without the pointer. `set_upgrade_offer(cost, affordable, next_points, next_mult)` only stores it — `_layout_labels` is the single renderer and reads `_hover`. Cost colour is the affordability read (`COST_COLOR`/`COST_DIM`). A `StaticBody3D` on `UPGRADE_PICK_LAYER` (128) over the whole chip is the click target, armed only while the view is open (`collision_layer` toggles to 0), because the whole cluster lies under the combos zoom zone on layer 8. Since the cell shows nothing, the Rampenlicht also lives on the chip (`set_spotlight` = golden breath, driven by `scene_root._set_spotlight_combo`), and so does the highlight of the rolled hand: `set_glow` pulls **package, pins and band** into gold (`HIGHLIGHT_*`), which is the only way the counting combination is findable among thirteen chips. The lid glass is deliberately excluded from that gold — tinting it, plus the bloom off the golden package, swallowed its own text. The cell stays the single data source: after any `set_score`/`set_level`, `scene_root._sync_combo_chip` copies its values onto the chip — never write chip text directly.
  Two traps the model imposes: `Pins` has no UVs and `Body`'s were shredded by the Blender booleans, so surface textures must be **triplanar**; and the 45° front band leans exactly on lid height, so it needs `BAND_SEAT_DROP` or its top edge z-fights the lid into a dashed line.
- **Der Rückblick (Erinnerungs-Modus)** — the pit's log: `RoundLog` (core, pure) records one entry per throw, take and Fumble of the **current round** (`round_log.clear()` at every `_start_new_round`), `LogView` (ui) is its panel, and `scene_root`'s `#region Rückblick` glues both to the table. Clicking an entry poses the **whole table** into that moment and the arrow keys (or the bar's ◀ ▶) step **one trigger at a time**. Four rules carry it. **Nothing is ever written back into `GameRun`** — its setters emit the signals that drive the ceremonies, so memory mode paints the *display layer* only (`_log_apply_display`), and `log_open` is the single new arbitration bit (the phase stays `IDLE`, no new `Phase` value): it silences every per-frame writer exactly the way `choosing` does in `_sync_screen_action_buttons` — plus `_update_pit_hover`, `_sync_transform_previews`, `_update_selection_glows`, `_refresh_ui` and `_sync_goal_bar`. Leaving the pit closes the log **including the restore**, arbitrated in that same per-frame place. **Recorded are display values and def COPIES, never a `GameRun` snapshot**: defs grow mid-round (Knochen, Glas), so `RoundLog.pit_slot_record` stores `def.instantiate()` and the **face index**, never just the value — material, rune and Pointer hang on the face, and a value can sit on several. **The take's steps come from the breakdown**, deep-copied at the one instant where it is finished and nothing is booked yet (right after `_remap_breakdown_to_slots`); `RoundLog.flatten` turns it into a linear step list in exactly the order `_play_take_animation` plays — combination, per die trigger its firings (each crit its own step) then its links, the deterministic links, the static charms, merge, post steps, result. Every step carries its own `base_after`/`mult_after` and the cumulative running values, so `_log_render_cursor` is an **idempotent painter, never an incremental animation** — that is what lets the cursor jump *backwards*. The recorded `charm_slots` travel in the entry so pad flashes never ask the live run (`_log_flash_charm`, never `_flash_charm_and_pad`), and money charms (Straßenmusiker, Rampenlicht, Goldrausch) are simply never called — their money stands as a finished number in `post_state`. **Posing reuses the pit's own vocabulary**: `set_slot_defs` → `tip_to_face` per slot → freeze + hard-set `Transform3D(_readable_upright_basis(...), …)` on the `_line_up_settled_dice` row formula (hard, not tweened — a step back must be instant). On open the live pit is mirrored (def **references**, transforms, freeze/visible/selected/values/face_indices/settled, overrides, `player_order`) and written back on close, so the pit stays aliased to `owned_pool`. The log opens **only between hands** (`phase == IDLE and not has_rolled_current_hand`, not while `route_pending`) — then nothing lies in the pit that a pose could disturb.
- **The shop's Sortiment-Sperre** — `ShopController.sortiment_locked` (toggled from a button in the shop header, next to the money; the footer is already width-bound on high hub levels). While it stands, `open()` rolls **nothing**: the existing `spreads` stay, including their `*_bought` flags and the page the player left on, so a locked shop is the same shop next round. Unlocking resumes the normal per-visit reroll. The flag lives in `ShopController` because the spreads already do — and it is cleared in the `run` setter, so a fresh run always gets a fresh shop. A hub upgrade mid-visit still re-rolls the current spread (`refresh_after_hub_upgrade`): the new slots have to become visible, and that outranks the lock. **Besitz sperrt** in the charm row: `_build_spread` filters every owned id out of the pool (premium pick and fill loop alike) and only falls back to the unfiltered pot when the filtered one runs dry — an empty slot is worse than a dublette.
- **Der Laden macht noch einmal auf** — closing the shop is no longer a one-way door. The FIRST close of a visit advances the round exactly as before; from then until the round is signed (`scene_root.shop_reopen_allowed`, the same window as the Werkbank) a **Laden** button stands in the hub's footer and reopens it. The re-entry rolls **nothing** (`ShopController.reopen()` shows the standing `spreads` with their `*_bought` flags and the page the player left on), does not call `begin_shop_visit()` (the Freispiel belongs to the visit), and opens no new betting window. Closing a reopened shop only does the display work — `shop_reopened` is the bit that keeps `_on_shop_closed` from advancing the round a second time; the pit stays the second exit and lands harmlessly in that same branch.
- **Die VITRINE — der Laden handelt körperliche Ware** — the shop page reads top to bottom as four bands with **FESTEN Anteilen**: **charm row** (digital goods — the card stays screen and swaps its 3D model for its FULL effect text on hover, see *Die Charm-Modelle*), the **GRAVUREN-Band** with the **KASSETTEN-PLÄTZE**, on which the sealed goods LIE (see below), the bay with **only the open dice**, and the footer. **Kein Band wächst mit Lizenzstufe oder Bestand**: `BAND_CHARM_UNITS` (26 u) and `BAND_FOOTER_UNITS` (6.2 u — measured against the tallest button the page ever carries) are authored in `u`, the Gravuren band is what its own row measures (heading plus one Stellplatz-Reihe, ~18 u — identical on every licence level because `SHOP_PACK_SLOTS` is flat), the bay is the only band with EXPAND_FILL and takes what is left, and inside a band the CONTENT shrinks (`_charm_metrics` derives the card height from the band and only the model size falls with the card count; the podest gets width, never height). A test holds every band rect byte-identical between hub 1 and hub 10. `ShopController` paints only the FASSUNG (`_vitrine_frame`, `draw_center = false`, the Magazin's recipe) and REPORTS its rect (`vitrine_rect_px` → `vitrine_pit_rect` = `PackDrawerView.pit_rect_in(strip, u)`, the `apron_bottom` pattern — ui/ never touches a body); scene_root stands `VitrineView` **on** that rect. **Es gibt keine Scheibe, und im Ruhezustand kein Loch**: the goods lie on the display surface itself, and nothing is between them and the player. A departure SINKS into the surface and the opaque screen mesh depth-tests away whatever is below (`VitrineView._sink_out`/`_sink_away` — the Ausgabefach's gesture); an ARRIVAL is the machine, and it cuts its own temporary hole (see *Die ZWEI ANKUNFTS-GRADE*). The bay is therefore **sichtbar oder gar nicht da**, and that switch has ONE decider, `scene_root._sync_vitrine_curtain`: shown while `phase == SHOP` and the shop page is the hub's visible page — a page that displaces it (Lexikon, title) takes its goods away and gives them back on return, **and a bay that is still building does not show** (`_vitrine_building`, see *Der Vorbau*).
  **UNSICHTBAR heißt: gar nicht da.** While the bay is not shown, its whole body is `visible = false` — goods and all —, and that visibility hangs on the ONE writer (`_set_vitrine_shown`/`_set_secret_shown` → `VitrineView.set_shown`), nowhere else: a bay left standing lies on the hub's start page, where the shop is not. Two measures keep the surface honest. A body rests `FLOOR_CLEAR` (0.03) above the plane, or its underside and the display fight in the depth buffer; and a die in a bay switches its floor pool off (`set_pool_enabled(false)`) — the pool would lie as a bright patch ON the display instead of under the die.
  **Der VORBAU.** Filling a bay costs real time — measured at the bench: six fresh die bodies plus their seating ~19 ms against a 16.7 ms frame, and ~30 ms more the first time, when the shared setup is paid —, and it used to land in exactly the frame the goods came in. So `_sync_shop_vitrine` builds in stages and **while the bay is not shown**: measure (two frames — the rect only stands once the page is laid out) → place the bay → next frame → set the stock hard (`GRADE_STAND`, the expensive part) → next frame → release `_vitrine_building`, show the bay and only then play the grade, which is cheap because every body already stands. Two caches carry the rest: `DataCellView` bakes the sort glyph **once per sort** into a shared oven (a SubViewport per cell cost ~11.5 ms — 90 % of a cassette's build; it falls back to its own oven if the tree will not take the shared holder), and `EngravingRenderer.bare_texture` does the same for the Sonderposten chip.
  **In der Bucht liegt alles AUF der FLÄCHE.** Nothing stands in a sales bay and nothing is sunk into one: `floor_y()` is the table plane itself, `lie_y(half)` seats a body's underside on it `FLOOR_CLEAR` above the display, and `cell_y()` adds what a cassette's contact fins reach under its origin. What a good needs is measured the other way round now — `content_depth()` is the tallest lying good (a die with its `SILHOUETTE`, or a lying cassette), and `sink_drop()` IS that measure: how far below the surface a body starts when it rises, and how far down it goes when it leaves. Both write the end state first, byte-identically to their hard writer, and only then drive the way there. `seat_hard` and `stand_in_pit` both stand on `CASSETTE_SCALE` — slit and strip carry the same cassette; "Pressen (n)" emits `press_started` BEFORE `open_press` — a signal, not state inference, because a direct-delivery press never enters `Phase.PRESS` — and the seated slivers **sink the rest of the way** as their displays turn into portals: die Dekompression — the cell's data streams into its reader. **The Magazin never retires**: the Schürze belongs to the bench, not to a flow, so Fach and console stand through the whole press cycle AND through dossier and Tausch — merely locked (`shelf_locked` = signed OR pressing OR dossier OR Tausch, so `slot_pack` refuses while one is running). `_drop_data_cells` on a run change is the single remaining exit; a skipped tween must never leak a body. Deliberately NOT `mark_reflective`: a body ON the glass mirrors beside itself as a grey smear. The Sonderbestand holds **two families** and both lie sealed among the rest, wrap band and all: the fixed-content special packs (`Engraving.SPECIAL_IDS` — Pointer and Veredelung) and the **Katalysator-Kassetten** (see *Die KATALYSATOR-KASSETTEN*). `Pack.pack_belongs` answers for a catalyst before it ever looks at a `fixed_engraving`, so cell, cap glyph, colour and `tidy_packs` key (which sorts on the `catalyst_id`) all come free; the cap deliberately does NOT distinguish the four — a sealed bay does not advertise its contents, and the hover names the card. Hover texts land on the **Hinweis-Schirm** in the console band's left flank (see below). One `CameraRig.Mode.WORKSHOP` zoom frames the whole corner, and everything in it shares **one** unit (`corner_unit` in `_setup_table_screen`), because a narrow drawer deriving `u` from its own width would render micro-type. Five rules govern the corner's size. `corner_unit` stays pinned to the **tray** width even though the bench is wider — hang it on the grown width and the drawers grow too, eating the gain. The bench's height is bounded by **the Schürze under it**, not by the display: the corner ends on the hub's bottom line, and from there the apron rises — bays (`SHELF_STRIP_UNITS`), seam, whole console band, seam. `WorkshopView.apron_units()` is that chain in units, and because the apron measures in `u = width/100` while the width follows the height, the equation closes: `h · (1 + apron_units · aspect/100) = span`, solved in one line (`_fit_workshop_rect`, no bisection left). The view derives the bay height back out of `apron_bottom`, so both directions meet on the hub line by construction. (Until the display became a rectangle this was the glass edge's job — the ellipse cut the last one and a half bays off diagonally; see *The endless floor*.) The bench's width is **solved, not authored** — `WORKSHOP_ASPECT` is gone. The page with the widest claim on the window is the **dossier** (die column left, 30-die grid right), so `WorkshopView.dossier_aspect()` returns the ratio at which *that* page closes flush: both content margins + the net column + the body gap + a 6×5 grid whose tiles exactly fill the content height. Everything but the window height measures in `u = width/100`, so the height cancels out and what is left is a pure ratio (≈1.96); `_fit_workshop_rect` feeds it into the same apron equation. On top of that ratio sits **one authored knob**, `scene_root.WORKSHOP_WIDTH_FACTOR` (1.2): the bench stands deliberately WIDER than the dossier demands, so the net row and the bays get more bank and the dossier keeps side air instead of closing flush. The factor is on the *aspect*, not on the width, and the span is fixed — so the solved height falls with it and the real width gain is only **+11.9 %** (993 → 1112 px measured), not the nominal 20 %; a true +20 % width would need ≈1.35. Two consequences of the solved width. The grid **fills its host** — the old 1.2 u inset inside `PoolHost` is gone, `CONTENT_MARGIN_*` is the only air, and the leftover is the container's whole-pixel rounding (≤1.2 %) plus whatever the width factor adds, never a band. And the table is finite: the solved width is capped at the display's right edge minus `WORKSHOP_RIGHT_MARGIN` (warned), with the height re-derived from the capped apron so the bays still land on the hub line. `APRON_FALLBACK_SHARE` died with the constant — a probe window without a reported line derives its apron from `apron_units()` itself, because a *share* is only ever true for one aspect. The corner has a **second zoom level** (`camera_rig.workshop_close`) reached only by **double-clicking empty workbench surface** — `scene_root._try_workshop_close_zoom` runs *before* the mouse forwarding (the window would swallow the event otherwise) and bails on any live button (`TableScreen.interactive_under`, the shared walker the hub's `interactive_at` also uses). The mode stays `WORKSHOP`, so click forwarding and the engraving ceremony carry over unchanged; right-click steps back to the wide view rather than out to the overview. Three rules make it work: the camera **stands still** there (no mouse look-around — the frame is brim-full, any pan would drag the trays in), reflections are off (like the title screen — the trays sit just outside the frame and mirror into it), and the view looks **straight down** (`WORKSHOP_CLOSE_TILT_DEGREES` = 0 vs. `ZOOM_BASIS`'s 15°) because from up close even a small angle skewed the workbench into a visible trapezoid. All view angles are one family — `tilted_basis(deg)` spans it, 0° = `TITLE_BASIS`, 15° = `ZOOM_BASIS`. The framing is solved, not tuned. The two axes are fitted **separately** (`WORKSHOP_CLOSE_MARGIN` for height, `WORKSHOP_CLOSE_SIDE_MARGIN` for width) because they land within ~1 % of each other, so a single `_fit_distance` flips between them; on a non-widescreen window the *width* binds and dictates the distance. Both margins are ≥ 1, so the corner always fits whole — the only question is where the leftover air goes, and that is the whole game: **above** the corner are the trays, **below** it is bare felt. So `_workshop_close_origin` seats the corner's **top edge** on the frame top and lets the slack pool underneath. The **wide** step is solved too since the apron grew the corner downwards (`workshop_wide_distance`, fed by `configure_workshop_target(center, half)`): a plain `_fit_distance` is **wrong** here because this view is TILTED — the corner's lower edge (the bays) stands nearer the camera and images larger, so the distance is solved from `dot(P−target, up) / ((dot(P−target, forward) + d) · tan)` over both edges, exactly as `_workshop_close_origin` does. `WORKSHOP_ZOOM_DISTANCE_BONUS` survives only as the lower bound, and `WORKSHOP_WIDE_MARGIN` (1.14) is plain framing air now: it once covered the ±5° look-around pan, which stations no longer have — the framing deliberately stays. `WORKSHOP_TOP_GAP` must stay ≥ 1.0: `tray_bounds` spans slot *centers*, so a smaller gap puts the bottom die row physically on the bench. And both `zoom_workshop_close`/`_wide` **emit `mode_changed`** although the mode is unchanged — the view changed, and without the signal every caller would have to remember to re-sync reflections itself. A **third level** (`camera_rig.die_focus`) belongs to the dossier die (see *Die Station ist Geschichte*). `CLAMP_HEAD_ROOM` was pulled up when the apron grew: the air over the clamp row is a WORLD measure (the hovering die does not shrink), the unit does — hang it on `u` alone and the close-up starts shaving the dice. **The bench NEVER empties**: net row, clamp dice and the dossier stand in every camera mode — `bench_focused` and `_sync_bench_focus` are gone, and the camera is no longer an input to anything the window shows. ONE exception, and it moves bodies, not the window: while the **pool tray is focused and the dice are still editable** (`scene_root._clamps_visit_tray()` = `Mode.POOL` and not `_dice_editing_locked()`), the clamp dice are **zu Gast im Tray** — the stages dematerialize (same grammar as the pit conflict, the nets stay) and the dice lie in their own seats; `_sync_clamps_visit` restages on the CHANGE only, hooked at `_on_camera_mode_changed` and `_sync_editing_lock`, and a clamp whose body lies in the pit stays absent per die (`_clamp_pit_conflicts`). Mid-round the holes stand as ever. What still clears the window is the **phase** alone: `clamps_on_bench()` = `_phase == Phase.STASH`, and with the pack flow dead only two phases are left (`INSPECT`, `EXCHANGE`) — the dossier or the Tausch-Wähler takes the surface and the clamp stages dematerialize with it. Consequences: the four clamp seats in the pool tray are permanent holes (`clamps_on_bench()` is BOTH the stage rule and the seat rule, `_tray_shows` asks it — permanent up to the tray visit above, whose `clamps_visiting` param on `DiceTrayView.seat_shows` fills them), and the dossier persists across camera exits — zooming away no longer returns the die to its seat, only `close_inspect` does.
  **The pit outranks the bench.** With the bench always populated, a clamped die drawn into the pit would stand in two places at once, so a clamp stage **dematerializes while its def lies visibly in the pit** and materializes back when the pit lets it go — the net under it stays either way, because the net is the record, not the body. The query is the pit's own (`DiceController.visible_slot_defs()`, the living instances of every visible slot), the decision sits in the one idempotent stage writer (`scene_root._rebuild_clamp_stages`), and the trigger is a **signal, not a poll**: `DiceController.pit_contents_changed` fires from `throw_slots`/`reset`/`set_slot_defs` plus `note_pit_changed()` for the two places scene_root writes `roots[i].visible` itself (the Rückblick's pose and its restore). `scene_root._on_pit_contents_changed` compares the conflict set **in `clamped_dice` order** and stands down when nothing really changed, so a reroll that draws the same clamp does not restage anything. The tray seat is untouched by all of this — it was a hole because the clamp claims the die, and the pit does not give it back.
- **Die EINE Ankunft des Magazins** — whoever delivers (shop, hub reward, charm, side bet, slot machine, Schwarzmarkt), the landing is the same act: the comet ends on the ANKER of the reserved spot, and there the cassette RISES out of the pit floor onto its sunk standing height. `scene_root._land_pack_in_magazine(workshop, uid, tint)` is the SINGLE caller of `WorkshopView.deliver_pack` — it marks the uid in `_rising_packs`, hands the reservation over (and flashes only when that uid really was under way, which `deliver_pack` reports) and fires `TableScreen.pack_arrival_flash` at the spot; the idempotent cell writer then shows that cell through `DataCellView.rise_into_pit(target, _pack_pit_depth())` instead of `stand_in_pit` + `materialize` (`_show_shelf_cell`, which also drops the pending pop — the rise brings its own flare). `_pack_arrival_px` is what every comet aims at: `WorkshopView.pack_anchor_px(uid)`, measured while the Fach stands and computed (`anchor_in`) when it does not — a withheld pack keeps its SPOT, so neighbours never shift when it lands. `_fly_pack_to_magazine` is the one helper for a delivery from outside (source and comet unchanged, target the spot); the shop's own purchase and the Schwarzmarkt's ride their own routes into the same landing. `rise_into_pit` writes the **end state first** (`stand_in_pit`, byte-identically) and only then drives the way there, so a skipped or killed tween leaves nothing owing — the `seat_hard` rule. The TRANSPORT is untouched by all this: goods travel as comets over the laid adern like every other light, and only the last stretch happens in the hole. Two deliberate exceptions: the **Frankiermaschine still books on arrival** (`_fire_charm_pack` grants at the impact and sets `_rising_packs` itself, because the pack does not exist before that moment and therefore cannot be reserved), and a grant that finds no place fizzles to a **money** comet to the treasure instead (`_fly_pack_fizzle`). `_rising_packs` is cleared with the run, so a Fahrt of the old run ends nowhere.
- **Die Presse & die Aufspannung** — the Werkstatt's upgrade system (spec: Obsidian page 20). **Nothing waits naked**: an upgrade exists only **sealed** (a `Pack` — every former stash source, Frankiermaschine/Schmuckkästchen/Abguss/slot prizes/Schwarzmarkt specials, mints sealed packs now, fixed contents via `Pack.fixed_engraving`) or **applied**; `owned_engravings` and the whole consumption economy are gone. The only legal engraving targets are the **Aufspannung**: `clamp_count()` random pool dice per round — **always exactly 4**, on every hub level (`GameRun.CLAMP_COUNT`, the one constant; the old 2/3/4/5/6 milestone ladder and `extend_clamped_dice` are gone, and a hub upgrade therefore does not touch the standing Aufspannung at all — the bench is the round's working surface, not an upgrade promise) — (`GameRun.roll_clamped_dice` → `clamped_dice` + `clamped_changed`; uniform, never queue order — the queue is player-sorted), stable through the round INCLUDING its shop, no ⚡ refresh, no swap-on-use. **A die whose body stands elsewhere leaves a HOLE, it never closes the row** (`scene_root._tray_shows`/`_tray_holes`, re-run off `clamped_changed` and off every change of the inspected die): a clamped die stands bodily on the bench and the dossier die on its own stage, and a second body in the tray beside either would break *a die is never shown twice* — but its SEAT stays its own, empty, at its own position. Since the bench never empties, those four seats are **permanent** holes, and they stay holes even while the die's body lies in the pit — the clamp keeps the die, it merely stops showing it (see *The pit outranks the bench*). **The dossier suspends the clamp holes**: while `Phase.INSPECT` stands the clamp stages have dematerialized off the bench, so their bodies are free and lie back in their own seats — the ONE hole is then the inspected die's own seat, clamped or not. Closing the page gives the clamps back to the bench and their holes back to the tray, both off the same `die_stages_changed` → `_sync_inspected_die` refresh. The rule has a single home, `DiceTrayView.seat_shows(def, clamped, inspected)` — the seating owns it, and it is the one part of scene_root's tray filling the suite can test at all. The pool tray is an **order, not a queue**: `DiceTrayView.fill` reads a `null` entry as an empty seat (`slot_defs[i] = null`, body hidden, so `find_slot_index` answers nothing and no drag or tap can grab it), and `_pool_tray_source()` is the single unfiltered seating (round-deck rest, or the whole pool in the shop) that both the tray fill and the pack-placement grid (`_pool_tray_layout`) read. Consequences: slot index ↔ pool index is true again, so `_deck_slot_position` is plain arithmetic instead of counting visible seats; `_animate_deck_shift`/`_animate_tray_reorder` simply skip a hole (there is no body to slide) and the rebuild afterwards carries the moved seat; and the pack-placement grid gets the clamped dice in place instead of appended into freed tail slots. The **discard tray keeps filtering** — it fills by `add_die` and has no seating of its own, so an absent die there just isn't in the row. The bench page is the Aufspannung's home — no WERKSTATT title: the **Netzzeile** (one interactive net per clamped die — `PressNetView`, under its projector with `CLAMP_NET_GAP` air so die and diagram never touch; it yields to the dossier and the Tausch-Wähler, **and the clamp DICE leave with it**: while one of those pages holds the window, scene_root dematerializes the clamp stages (`FloatingDie.dematerialize`, `under()` is visibility-gated so a hidden die answers no pick) and materializes them back staggered when the flow ends, same bodies, never freed; a running press and a lying Ablage leave them STANDING, they are the targets) sits over the six **press slots** (a slotted pack is a reservation the Magazin withholds from its Fach, and a click on a filled slit returns it to its own spot — that is the slit's ONLY role, there is nothing else to click there), under them the Magazin with each pack as its own Data-Cell; packs never render as cards in the window.
  **Die Güte ist tot, es zählt die MENGE — und die Menge ist eine KETTE.** No Reihen, no adjacency, no Stufen out of the press: every minted piece is flat (`stufe` 1, `applications` 1). The old 1/3/5 Ausbeute roll is gone; in its place stands the **MULTICAST** (Ogre-Magi grammar): a pressed pack **triggers once always**, then rolls — a hit triggers again and rolls again, chained, up to the limit. The pack's size sets the **base payout per trigger** (`PhantomPress.BASE_PIECES`, indexed by `Pack.TIER_*`: **1 / 3 / 5**); the tier multiplies what each cast delivers, never how often it casts, so the piece ratio 1 : 3 : 5 is **chance-independent** and `Pack.TIER_PRICE_FACTORS` stays put whatever the chain does (a test walks every rung and asserts it).
  **Chance and limit are PARAMETERS, and they grow with the casino.** `PhantomPress` stays pure: `roll_multicast(rng, chance, cap)`, `expected_triggers(chance, cap)` and `expected_pieces(tier, chance, cap)` all take them, defaulting to the bottom rung (`MULTICAST_CHANCE` 0.5 / `MULTICAST_CAP` 3) for every caller without a run. The milestone table lives there too — `PhantomPress.MULTICAST_LADDER`, on **the same hub steps as the capacitor rows** (1 / 3 / 5 / 7 / 10): chance **50 / 56 / 62 / 69 / 75 %**, limit **×3 / ×4 / ×5 / ×6 / ×7** (`base_chance`/`base_cap`, `max_cap()` = 7 is what any worst-case display or test measures against). **`GameRun` owns the queries** and they are the ONE resolution: `multicast_chance()` = hub rung + Zündverstärker (×`deal_bonus_factor()`) + the side-bet boost − Zündhemmung, clamped into `[MULTICAST_CHANCE_MIN, MULTICAST_CHANCE_MAX]` (5 % … **90 %** — a multicast that always fires would stop being a chance, the same rationale as the Pointer's cap); `multicast_cap()` = hub rung + Kettentreiber (×factor) + the boost, and then **Kurzschluss overrides it to 1, absolutely**. `open_press` reads both ONCE per grip (every reader casts on the same chain) and **consumes the boost** there — `press_boost_pending` is a one-shot that survives rounds but not a pressing, and dies with the run. Every display threads the live pair instead of reading constants: `Pack.multicast_line(tier, chance, cap)` (shop card + hover, fed from `ShopController.run`) and the Multicast-Schirm. **Every trigger rolls its own icon** out of its sort's icon set, **weighted by rarity** (`Engraving.RARITY_WEIGHTS`, the single source, mirroring `Charm.RARITY_WEIGHTS` and continued down to EPIC/LEGENDARY — measured: a COMMON verb ~26 %, an UNCOMMON ~14 %, the EPIC Meißel ~3 %) (`PhantomPress.ICONS` — Zahlen: the six ladder verbs Kerbe/Überdruck/Politur/Meißel/Schleifstein/Aufholen; Material: the six materials incl. **Kupfer** (`copper`: +1 ⚡ scored, doped +2 ⚡, overflow past the cap pays $2 each); Runen: the six `rune_` engraving ids). Duplicates inside one pack are the normal case, not a bug. A **Fixinhalt-Paket** (`Pack.fixed_engraving` — both Sonderposten, Abguss casts, Schmuckkästchen materials) is **exempt from the chain**: no multicast roll, no count roll, no icon roll — ONE trigger carrying `pack.count` copies of its one icon, and it runs through the same press path as everything else (the old "direct delivery never enters the press" special case is gone).

  **Die drei PAKETGRÖSSEN** (`Pack.TIER_NORMAL/TIER_GROSS/TIER_KOLOSSAL`) are the base payout per trigger and nothing else. Only a pressable pack carries one — `Pack.tierable` bars Fixinhalte (they never roll) and Katalysatoren (they throw nothing); the guard is what keeps `tiered()` from decorating a Sonderposten with an adjective it cannot honour. `tiered(pack, tier)` is the single write path: it sets the field, prefixes the German adjective (**Großes / Kolossales** — every sort name ends in "-Paket", neuter, so one form serves all three) and scales the price by `TIER_PRICE_FACTORS` (**1.0 / 3.45 / 5.75**). Those factors sit deliberately 15 % **above** the piece gain (1 : 3 : 5): the surplus is the price of DENSITY — the same loot out of fewer Magazin spots, fewer of the six readers, and fewer pressings, whose ⚡ price climbs with each one. The resulting shelf prices are Zahlen $5/$17/$29, Material $6/$21/$35, Runen $7/$24/$40 (the Sonderposten stays flat at $30, so a Kolossal Runen-Paket is deliberately the dearest thing on the shelf and pays ~$4 per expected piece against the Standard's ~$7). **Two sources mint a big pack, and neither is a grant**: the shop rolls its size (`ShopController._build_spread` rolls `Pack.roll_tier()`, weights `TIER_WEIGHTS`, 60/30/10, per engraving-pack slot) and the **slot machine earns it by run length** (`SlotMachine.PACK_LADDER`, see *Fumble-Automaten*); every grant path (hub rewards, Frankiermaschine, Stresstest prize, Füllhorn, Abguss, side bets, `Pack.by_type`) calls `roll_engraving_pack()` without an argument and therefore mints Standard. The shop card prints the decorated name plus "n Gravuren je Auslösung" where it used to print "1 Gravur" (`Pack.pieces_word` is the one singular/plural source card and hover share), and the hover adds `Pack.multicast_line(tier)` = base + the flat chance + the cap; the Magazin's hover title is the decorated name for free. `count > 1` is the **Bündel**: one Data-Cell carrying several identical pieces, never a stack of cards — the Schwarzmarkt is the only source, and pressing it throws its whole content out of one reader. The `EtchingEffects` ladders and `Engraving.stufe_text` survive: the hover text is the Stufe-1 line, and higher rungs wait for a future source. A **rune** line leads with the rune's own `description` — its WIRKUNG — and only adds the placement count above one application; a line that merely counted setzungen said nothing about what the rune does, which is the one thing the hover exists for. `PhantomPress` (core, pure, injected rng) is the single source for icons, chances and pieces; no charm adds to a pressing any more (the Füllhorn moved to the round end, see the round-end ceremony). **The result carries the TRIGGER STRUCTURE**, because the ceremony plays it: `open_press` returns `readers[i]` = an ordered array of trigger groups (a normal pack: `BASE_PIECES[tier]` uids per group; a Fixinhalt: ONE group with all its copies) and `reader_uids[i]` = the same uids flat, for every caller that only wants the list. `PhantomPress.payout_groups` is that structure (the flat `payout` is only its one-line reading), and `GameRun._press_pack_groups` is where the Fixinhalt exemption lives. A **Katalysator** reader is the third shape and the simplest: an EMPTY trigger array — it gave, it did not throw.

  **Die KATALYSATOR-KASSETTEN** are the Sonderbestand's second family (`Pack.catalyst_id`, the four ids in the one table `Pack.CATALYSTS` with name, Wirkzeile and Ladenpreis; `Pack.catalyst(id)` is the single factory and returns `null` on an unknown id, because a nameless card in the Magazin is worse than no card). They carry **no content at all** — not a `fixed_engraving`, not a sort, not a tier (`Pack.tierable` bars them next to the Fixinhalte) — and they pay **nothing**: slotted into a reader they modify the ONE pressing they stand in and burn with it. **Occupying a reader IS their cost** beyond money; there is deliberately no catalyst slot. Four cards: **Treibladung** ($14, Multicast-Chance +20 %), **Taktgeber** ($14, Multicast-Limit +2), **Doppelmatrize** ($18, +1 Grundstück je Auslösung — Standard 2, Groß 4, Kolossal 6) and **Erdungsklemme** ($8, dieser Griff verbraucht die Pressung der Runde nicht). Stacking is legal and **additive** (`GameRun.catalyst_terms(packs)` → `{chance, cap, base, free}`), and the whole point of the design is that **the terms travel INTO the existing queries, never beside them**: `multicast_chance(bonus)` and `multicast_cap(bonus)` take them as parameters, so the 5–90 % clamp still bites a stacked Treibladung and **Kurzschluss still overrides a stacked Taktgeber to 1, absolutely**. Composing outside and skipping the queries would have quietly unmade both, and a test nails each end. The base term rides `PhantomPress.base_for(tier, bonus)` down into `payout_groups`, so the press stays pure — and the **Fixinhalt exemption holds**: a fixed pack rolls nothing, so the Doppelmatrize does not touch it. The `free` term IS the Erdungsklemme: a grip carrying one does **not consume the session's one pressing** (`press_uses` stays 0, see *Pressen ist gratis*) — she preserves, she never revives: once the pressing is spent, no grip presses, Klemme or not (a second Erdungsklemme in one grip is therefore wasted; `free` is a switch, not a counter). **A grip of pure catalysts cannot press**: `open_press` partitions the chosen indices and returns the empty result untouched when no loot pack stands among them (nothing consumed, `press_uses` unmoved), and `WorkshopView.can_press()` asks the same question through `loot_slot_count()`, so the seat disables and the Hinweis-Schirm says why. Consumption is the pack rule verbatim — including **the Zwinge's survival roll**, which covers a catalyst like any other cell. Sources: the shop's Sonderposten single (see *Sonderposten im Handel*), the Schwarzmarkt's Sonderbestand slot, and every grant path via `_stash_pack` (a fizzle pays the flat `PACK_FIZZLE_MONEY`, knowingly undervalued). The Reinraum side bet and the Füllhorn stay engraving-only.
  **Pressen ist gratis — und EINMAL je Sitzung.** The ⚡ price is gone entirely (no `press_cost`, no pay comet): the one brake is `GameRun.press_allowed()` = `press_uses == 0`. `open_press` refuses untouched once the session's pressing is spent — Erdungsklemme or not, the Klemme prevents consumption, it never refunds a spent session. `press_uses` resets only where the workshop session closes — the signature (`scene_root._commit_round` calls `reset_press_cycle()`) and a fresh run — deliberately **not** at `advance_round`, so the one pressing spans shop plus pre-commitment window. The state never stands on the button (its rect is fixed): hovering the seat writes it onto the Hinweis-Schirm ("Die eine Pressung dieser Runde steht bereit." / "Die Pressung dieser Runde ist bereits verbraucht." / the Erdungsklemme preservation line / — for a grip of pure catalysts — the line that says why nothing presses; only that last one keeps the RED tint, and `show_hover_info(title, body, tint)`/`chip_hint_at` keep carrying the colour for it).
  **Die Pressung ist EIN Griff.** There is no state between roll and loot, so there is no "Nehmen": `GameRun.open_press(pack_indices, rng)` refuses outright when the session's pressing is spent or no loot pack stands in the grip, otherwise partitions it into catalysts and loot, consumes the session's pressing (`press_uses += 1` — unless an Erdungsklemme stands in the grip), rolls counts and icons, mints the pieces into `press_pieces` (each stamped with a `piece_uid`), consumes the packs — catalysts included, Zwinge roll and all — and emits, atomically. It returns `{"pieces", "readers"}`, where `readers[i]` are the uids reader i threw; the view relays that as `press_rolled(sorts, readers)`. The seat therefore carries **two** labels in its one measured rect: "Pressen (n)" and, once loot lies with an empty console, "Fertig" — a slotted pack takes the seat back from the Fertig, because pressing again is a legal move and the way to the Fertig is one eject away.
  **Die ABLAGE: die Beute liegt auf dem Glas.** Nothing waits in a reader any more. After the press each piece lies as a bare icon chip in a strip along the window's bottom interior (`ablage_rect()`, two rows filling the free band below the net row — height and row count are measured against that band, so the chips lie under the diagrams instead of on them) — the bare-good grammar (kein Panel unter einem physischen Ding): every chip is a `Button` with `StyleBoxEmpty` in all five states, drawing only its engraving icon over a soft sort-coloured glow (`PackDrawerView.COLORS`, the single colour source), hover lifts and brightens, and the held piece wears the gold frame. **A chip's spot is a pure function of its `piece_uid`** (`ablage_spot`: hash → lattice slot + hash-derived jitter, clamped into the strip): a rebuild reproduces the heap byte-identically, a placed piece never moves its neighbours, and an unseated piece returns to ITS own spot. Overlap is allowed — it is a heap, not a Setzkasten. But the heap is only where the meteors LAND: the last impact calls `tidy_ablage()`, and the pile **glides into one ordered row** — `ablage_order()` sorts by sort (`Pack.SHELF_ORDER`, so the row reads in shelf order), then rarity **ascending** (häufig left, episch right — the row grows toward the valuable), then engraving id (identical pieces stand together), with the uid breaking the tie because `sort_custom` is not stable. The row centres each line in the strip at a fixed pitch and squeezes its columns rather than growing another line past `ABLAGE_ROWS`. Two rules keep it honest: **the order is state, the glide is display** — `tidy_ablage` commits `_ablage_order` before any tween, so a hard landing (run change, unfocused bench) or a rebuild mid-glide lays the finished row down hard; and **the row FREEZES** — a placed piece leaves its slot empty instead of reflowing the neighbours, and only the next pressing re-sorts everything (its new pieces land scattered on the standing row and then the whole pile lines up again). **Identical engravings share ONE place**: the row's slots are per engraving id and the copies lie exactly on top of each other and only the front one is DRAWN (`_sync_chip_cover`) — the stack shows ONLY as the gold ×n on its icon, never as a brighter chip, because overlapping glows would make the count readable twice and offset copies were unreadable in the strip. The copies glide together first and cover each other at the target, so the merge is visible. The number rides the chip that lies in FRONT (the held one if it belongs to that place, else the last seated), or the selection would cover it. That count is **live** while the slot is frozen — `_ablage_stacking()` recounts depth and size from the lying pieces at every build and at the tidy, so placing one copy leaves the stack standing with a smaller number instead of a lying badge. The strip is an absolutely positioned overlay hanging on the WINDOW, so an empty Ablage and one with thirty chips lay out the base page identically (test-asserted). **The one-slot-per-engraving rule is also what caps the strip's load**: 25 pieces out of one Kolossal reader can occupy at most the 6 icons of their sort, and six loaded readers at most the 18 icons of all three — measured at the real bench, 60 pieces collapsed to 11 slots and 25 to 5, both inside a single line of the two-row strip at full chip size, so the base geometry needed no widening for the big packs. Selection runs on the uid (`hold_piece(uid)`, `held_uid()`), and after a placement `_sync_held` keeps the hand on the **same engraving** as long as another copy lies there — setting a row of Kerben should not need a fresh grab after every click — and only when that stack is spent does it fall to the **left end** of the row (`ablage_order()[0]`, which is the leftmost slot even on a frozen row, since the slots were handed out in exactly that order). Advancing to the vacated *array* index was the old rule and is what made the selection jump. Gone with the readers: `press_slot_pieces()`, the reader stamp `"slot"`, the ×n applications badge and the spent-display darkening.
  **Die Zeremonie: Portal, Ketten & Meteore.** The reader display is a `PressPortalView` with six states — dark, booked (sort glyph, rim in the sort colour, straight from `_selected_packs`; a catalyst books in Sonderbestand violet with the corner seal, the same drawing its cell carries), swirl, discharge, the **Einspeisung** (`inject(delay)`, `INJECT_TIME`: the catalyst's ONE beat — the seal sinks, a core bursts into an expanding ring, and then the reader stays dark, because it gave instead of throwing; scene_root routes it from the empty trigger array, `if (readers[slot] as Array).is_empty()`, so no swirl and no meteor ever leave it) and the **Multicast-Schlag** (`multicast(n)`: an expanding ring plus a "×n" whose size and peak brightness ramp with n, capped under `MULTICAST_PEAK` so the three channels never merge into white and swallow the digit; ×1 shows nothing — it is not an event). `press_started` still fires BEFORE the booking so the seated cassettes decompress with full sockets; then scene_root's `_on_press_rolled` withholds every minted uid from the pile (`withhold_press_pieces`) and starts **one chain per reader** (`_run_press_chain`, staggered by `PRESS_PORTAL_STAGGER`, all running CONCURRENTLY — the torrent survives, only each pack's nachlegen is now legible). Inside a chain the order is strict and SEQUENTIAL: swirl → meteor(s) of trigger 1 → **land** → `multicast(2)` + `flash_multicast(2)` on the Schirm → meteor(s) → land → … A trigger now carries 1, 3 or 5 pieces, and they fly as a small volley staggered by `PRESS_METEOR_GAP` whose LAST landing releases the next flare — the trigger, not the piece, is the beat. Nothing overlaps within a reader; `PRESS_TRIGGER_GAP` is the air between a landing and the next flare. Booking stays atomic in `open_press` — the SEQUENCE is display only. A meteor is a LOCAL flight inside the corner, no LED strip: `TableScreen.press_meteor(from, to, color)` samples a quadratic bézier (`_arc_path`, `ARC_LIFT_*`) over the console seam and feeds the shared `_pulse_along`; `_launch_press_meteor` returns its travel time and the chain awaits exactly that. **The reveal happens at landing**: `land_press_piece(uid)` is what puts the chip on the glass (scale-pop plus flare), and until then it does not exist visually; `tidy_ablage` still runs on the LAST landing of the whole press, because `_withheld` empties across all readers, not per chain. Three invariants hold the whole thing: booking is finished before the first swirl frame; the volley carries a **deadline** that must outlast the LONGEST possible chain — `_press_chain_deadline` sums stagger + swirl + per trigger (`PressPortalView.MULTICAST_TIME` + `PRESS_TRIGGER_GAP` + `PRESS_METEOR_MAX` + the group's own `(n−1) × PRESS_METEOR_GAP`) over the real trigger AND piece counts and adds `PRESS_METEOR_GRACE` — it therefore covers the 25-piece single-Kolossal worst case and six of them at once, then `_land_press_pieces` runs over the whole volley — `land_press_piece` is idempotent, so a piece that already landed notices nothing) because withholding is display state that only an impact clears, and a single missed impact would otherwise hide that piece FOREVER and leave the shelf locked with it; and `pressing()` is literally "something is still withheld" — so the shelf lock (`shelf_locked()` = signed OR pressing OR pack flow OR dossier; **a lying pile no longer locks anything**) releases with the last landing, and a lapse or run change prunes the withheld set (`_prune_withheld`) instead of leaving the automat running forever. Every await is guarded by the run instance, and a rebuild mid-flight simply lays the pile hard.
  **Der Platzierungs-Schritt.** Every piece is placed BY HAND on the clamp nets — legal cells glow, directed tools keep their two clicks, and the clamps are the ONLY targets (`press_target_allowed` = `is_clamped`); the step persists across camera exits (the dossier's grammar) and ends only with the gold **Fertig**, never by the empty hand alone — `placing()` = pile OR journal non-empty, so wet re-seats live inside the step. **Fertig is always available** (only `editing_locked` bars it) and is the one place unused loot turns into money: it cashes every piece still lying at `PhantomPress.FIZZLE_MONEY` (**$1** — at two to ten pieces per pack a $2 fizzle would out-earn the pack prices) before it books anything else. Selling a single piece is deliberately not a move. Every apply books through `GameRun.apply_press_*` — never a direct def write from the view — and afterwards no piece exists anywhere: **keine losen Aufwertungen**. Placements are WET until **das Anwenden**: every `apply_press_*` journals the exact before-state of all touched faces (`press_journal`; touched = computed by diffing all six faces, never declared — safe because between placement and Anwenden the clamped dice never roll), `unseat_press_piece` restores byte-identically through the single write paths, and a piece is re-seatable iff no later piece touched any of its faces. **Nothing is real before the button**: `apply_press_placements()` cashes the leftover pile and hardens the cast — and that is the ONLY money the press ever pays; the cut-off — the signature (`scene_root._commit_round`) or the next `advance_round` — instead calls `lapse_press()`, which unwinds every Setzung newest-first through the checked unseat path, drops the pile, and pays **nothing**: was nicht angewendet wurde, hat nie gezahlt. A second press deliberately does NOT clear the journal — accumulation is legal, and the wet cast stays wet. (`piece_uid` is both the chip's identity on the glass and the identity of a piece across its journal entries.) The **Zwinge** no longer touches the cast at all: it rolls per pressed Data-Cell in `open_press` (`CharmEffects.pack_survive_chance`, 25 % per copy, capped at 75 %, fixed-content cells included), and a survivor throws its full Multicast-Kette AND stays in `owned_packs` — the result dict reports it as `"kept"`, and the shelf's normal rebuild off `packs_changed` puts the cell back. Wet placements stand as green badges on their net cells (`press_face_marks`); clicking one lifts the piece back into the Ablage (set badges dim and inert); they answer only to `editing_locked`, never to the bank block. Kupfer's ⚡ flies as a Funkenflug-sibling volley (book first, fly afterwards; run-instance guard only — a phase guard would truncate the light mid-take). **There are no premiums**: no pool-wide placement, no sealed bonus pack, no free Übertaktung (`free_overclocks` survives unfed, so the chip's GRATIS hover simply never shows). The old 3D `PhantomDie`, its `EngravingIconOven` and `PressReelView` are all gone; the portal and the Ablage chips draw their icons straight from `EngravingRenderer` (bare, process off).

Since the dice packs died, the dossier is the ONLY page that stands a die on the bench; a bought or won die lies in the **Ausgabefach** instead (see *Das AUSGABEFACH*), and the die shown there is a body of that tray, not a `FloatingDie` stage. - **Die Station ist Geschichte, das DOSSIER ist ihre Rückkehr als reine Auskunft** — `DieInspectorView`, the gold workpiece stage and the whole engraving-station page died with the inline Platzierung: placing and re-seating happens on the clamp nets themselves (`PressNetView`), and nothing on the new page edits anything.   **Die Inspektion** is `WorkshopView.Phase.INSPECT`, a page of the bench window — and it is the page the **window's width is solved against** (see *The workbench corner*): left the die itself as a real `FloatingDie` over its stage (`scene_root.inspect_stage`, spawned off `die_stages_changed` with a generation guard like the data cells; it waits **two** frames now, because the column hangs between two stretchy slacks and its centre only stands once the box has handed out the leftover), under it its Würfelnetz plus name and Augensumme — the hover-card content grammar, and its cells answer through the same `net_hint_at`/`DieNetView.hint_for` plumbing as every other net —, right the 30-die grid (`DiceGridView`, `reorder_enabled` **on**, filling its region) with the shown die highlighted — tapped it switches the dossier, DRAGGED it rearranges the pool, which is the tray's own split and, since the Paket-Platzierung died, the second home of `reorder_pool`. - **The endless floor** — the felt doesn't end at the screen: `TableGround` (in `room.tscn`) lays a **3×3-tiled** plane just below Y = 0 with `assets/shaders/table_ground.gdshader`, which runs the *same* felt math as `table_felt.gdshader` over **virtual screen UVs** extrapolated from world coordinates (pattern stays in phase across the glass edge) and takes its visibility from an authored **emission pool** (`glass_energy` = the glass shader's 1.2, so the seam tone matches exactly) fading out past the screen rect — the scene lights (range ~55) can't carry a floor that size. - **Light routing (core rule)** — every comet/meteor between screens rides the laid LED-strip network (`LedStripView` paths, chained via `_route_via_strips`); nothing flies free across the felt. **Alles fährt als Licht über dem Filz** — there is no second channel. Scoring, ⚡ and money travel as comets and chips, and a physical good (a bought cassette, a Sonderposten, a traded die) sinks out of its bay and then travels the very same way. Two named routes carry the goods: `pack_delivery_comet(from, color, target)` (the hub→workshop ader, ending on the Magazin spot or in the Ausgabefach) and `secret_delivery_comet(from, to, color)` (Schwarzmarkt ader → hub → workshop ader, chained through `_route_via_strips`). The combo chips hang on that same network: `combo_wiring` is one `LedStripView` carrying the whole chip net in `rail_paths`, kept deliberately sparse: only the **shared** vertical buses (`combo_bus_xs` keeps an x only if it borders two columns — the outer ones served one side each and littered the felt), ONE cross rail along the cluster's bottom edge tying them together, and per chip a single stub per adjacent bus on the middle pin row. **Both external adern must land on a corner of that net, never on open track**: the hub ader enters at the bottom-right corner (right bus × cross rail, `link_hub_to_cluster` overrides the usual center entry for exactly this), and the score ader leaves at the top of the **left** bus (`link_score_strips`) and runs the cluster's top edge — which doubles as the upper cross connection, so the right bus needs no separate top rail. Light therefore crosses the net diagonally, hub corner to score corner. - **Augen sind Materie** — when a die's face value changes mid-count (Knochen, Glas, Helium/Strahlungsdruck, Miasma — everything riding `MaterialEffects.mutate_value_once`), the change *travels* as small glowing pips: **in from the pit's top edge = gain, out to the pit floor = loss**. That is the third motion channel next to rising money and falling base/mult numbers, and its direction is the whole grammar — nothing else in the pit moves matter into a die. Denominations are **5 and 1** (`TableScreen.split_eyes`, the greedy mirror of `ChipStackView.split_gain`); the five is bigger and brighter, never a single fat pip. All arithmetic lives in the **physical** domain: the breakdown's `value` is the *counted* (shown) number, so the firing also records `value_before`, and `scene_root._play_eye_pips` derives `post_mutate = value_after + miasma_self_loss` — `value_after` already nets the exhale. Volley A carries the die's own mutation, Volley B the Miasma, Volley C the **Radon-Bestrahlung** (mechanically the Weihrauchfass case: nothing falls out, the recipients gain, so it reuses `_rain_miasma_gift` in Radons eigenem Glühen). Ticks are **display only** and **absolute**, never relative increments (booking stays in `apply_take_effects` after the ceremony, which is also the ultimate corrector): a gain ticks on **arrival**, a loss on **launch** — the eye leaves the die — and each tick carries a planning-order sequence number, so a late pip from an older firing is *dropped* rather than rewinding the digit (`_plan_eye_tick`/`_eye_tick_applied`, the same monotonicity as `_score_applied`). The Radon spread rides the same channel and the same planning rule. The **Miasma relay is conservation-correct**: `spread_miasma_once` hands the full halved amount to EVERY other scored die, so each landing pip spawns one pip *of its own denomination* per recipient — summed over the volley each recipient gains exactly the spread. The relay is **planned at volley time, not at landing**, or its ticks would outrank the recipient's own later firing. With the Weihrauchfass (`self_loss == 0`, spread > 0) nothing falls out and the recipients' pips rain straight from the top edge. The floor is `TableScreen.pit_floor_y(x)` — the topmost obstruction in that column, sharing the net-card clamp with the gain numbers — and every floor landing fires a pit-wave impulse in the pip's own colour (`pit_impulse` takes an explicit colour now; without one the kind dict still decides). Fire-and-forget: the take ceremony **never awaits a pip**, each launch and tick guarded by `phase == Phase.SCORING` plus the run instance like `_fire_die_money`, and when no pip launches the digit is simply set hard — correctness never hangs on the animation. v1 boundary: the **up face only**. Pointer and deterministic links mutate a face nobody sees and get no pips (they carry no `value_after`), the take-effects tail (Radon, Gleichrichter, Kontrastmittel) keeps its existing flares, and the Rückblick **paints, never animates** — pips live in the live `_play_die_pulse` path alone.
- **Reflections** — no SSR in `gl_compatibility`. `ScreenReflection` (`screen_reflection.gd`) is a `SubViewport` with a mirror camera (main camera mirrored across the plane, negated-X basis) rendering reflection-layer (`1<<10`) instances into a texture. `assets/shaders/screen_glass.gdshader` (`render_mode unshaded`, so scene lights don't paint the glass) blends UI + masked reflection; window rects/radii are pushed into its `window_*` uniforms by `TableScreen._sync_reflection_windows()`. Its HOLES are separate from all that: `pit_rects[MAX_PITS]`/`pit_radii` (a list of at most 5 — Platz 0 dauerhaft die Magazin-Grube via `set_apron_pit`, der Rest die flüchtigen Hebebühnen-Schächte via `set_lift_pit`/`clear_pit`) discard the picture and cost no `MAX_WINDOWS` place — a hole doesn't reflect, it is gone. `TableScreen._sync_pits` is the ONE writer of that list, and it feeds BOTH shaders: the glass in display pixels, `table_ground` in world XZ (`pit_bounds`, pushed through the ground material `scene_root` reports once via `set_ground_material`). Two writers would eventually leave a hole standing. `ScreenReflection.mark_reflective(root)` ORs the layer bit onto `VisualInstance3D`s.
- **Two camera systems, and they exclude each other** — **Fokus** is the old table: discrete stations at solved distances (texture resolution for the Schwarzmarkt, fitted rects for title and workshop-close, and the **hub**: `hub_distance()` solves the tilted fit over both edges the way `workshop_wide_distance` does — the hub is the tallest window on the table and its lower edge stands nearer the tilted camera, so the flat `ZOOM_DISTANCE` cropped the footer row off the bottom; `configure_hub_target(center, half)` carries the measured half-extent in, `HUB_MARGIN` is the air, `ZOOM_DISTANCE` the floor), entered by a left-click on a zone, left by right-click. It is the FRAMING system, not the interaction system: what may be operated hangs on visibility, not on the station (see *Sichtbar heißt bedienbar*). **Three stations stand locked, the rest look around**: hub, workshop (all its levels — close-up and die focus keep `mode == WORKSHOP`) and the title are fixed frames — their window fills the image, a pan would only shove it (`CameraRig._tilt_frozen_mode()` is the one gate). Every other focused station tilts with the mouse at the zoom angles (`ZOOM_TILT_MAX_*`, ±5°/±16°, shared with the parked Freikamera), and the drag locks (`set_tilt_locked`) are live there again. What still keys off the discrete `Mode` is the STAGING (reflections, the pit's route cards and supply tray, the clamp dice's tray visit), so a camera parked between modes has no defined answer for any of it. **Freikamera** is the answer to that: its `Mode` stands on `OVERVIEW` the whole time — the established "nothing focused" state, so every one of those consumers keeps a defined answer while the camera stands in the middle of the felt. `CameraRig.free_camera` is the bit, read the way `log_open` is read. Framing and readability guarantees are deliberately **waived** inside it: it may stand closer than any station and higher than the overview, and nothing promises a window is legible there.
  **Switching is automatic and needs no mode key.** The first WASD press or the first wheel notch in any lateral view enters the Freikamera; a left-click on an available zone leaves it into Fokus at that station; right-click leaves it to the overview; and **any scripted flight wins** — round end → hub, shop opening, title, game over. That last rule has exactly ONE home: `_animate_to` clears `free_camera`, so every caller of `zoom_to`/`zoom_out`/`show_title`/`zoom_workshop_*` inherits it and no call site has to remember. Its counterpart is that `zoom_out` must fly **although the mode already says OVERVIEW** — that is the one early-return the Freikamera has to punch through, or right-click would strand the camera mid-table. Entry keeps the pose the player SEES: no descent, no jump, only the resting angle blends from the overview's 20° onto `ZOOM_BASIS`'s 15° over `FREE_SETTLE`, while the mouse tilt runs on unbroken. Dead to it are the TITLE HUD, the Rückblick, both vertical workbench levels (close-up and die focus — their frame is brim-full), every live drag and a running click flight (`scene_root._free_camera_allowed` + `begin_free`); the vertical levels also keep their OWN wheel (down = one step back) and their click/double-click entrances, so only the *lateral* wheel became free zoom.
  **Movement and zoom are both measured, never typed.** The keys are `nav_up`/`nav_down`/`nav_left`/`nav_right` (physical keycodes, `Input.get_vector` so diagonals normalize and opposites cancel); the directions are `ZOOM_BASIS`'s image axes flattened onto the table (`GLIDE_RIGHT`/`GLIDE_UP`, image-right = world +Z, image-up = +X), the velocity is lerped over `GLIDE_ACCEL`, and the look point is clamped to the display rectangle plus `GLIDE_BOUNDS_MARGIN`, measured off the real surface (`scene_root._setup_glide_bounds`). **Speed hangs on the height** (`free_speed`, `GLIDE_SPEED` at `ZOOM_DISTANCE`, floor and ceiling `FREE_SPEED_MIN`/`FREE_SPEED_MAX`) — the flat 36 m/s is unsteerable over a die and a crawl from up high. The wheel sets a zoom GOAL (`zoom_step_distance`, multiplicative per notch so the steps stay fine where the view is close) and `free_step` approaches it exponentially; each frame's actual ratio is applied about **the point under the cursor** (`zoom_anchor`, the cursor's plane point re-asked every frame), so what one points at stays put. Clamps: `FREE_ZOOM_MIN` near, `overview_distance * FREE_ZOOM_MAX_FACTOR` far, the overview distance itself measured in `_ready` from the authored camera. Zooming at a clamp does nothing.
  **SICHTBAR HEISST BEDIENBAR** — the free camera has NO input branch of its own any more; it walks the same chain as every station in `scene_root._unhandled_input`: forwarding first, then the physical grips, and the zone click LAST, as the fall-through. Two rules carry it. **A window forwards when it is really to be seen**, whatever the camera does: `TableScreen.window_takes_pixel(window, rect, pixel, is_click, focused, flying)` is the ONE decider (`visible` + rect, then MOTION over the whole surface for clean button hover, but a CLICK only on a real control — `interactive_under` — while the camera stands elsewhere, because otherwise the window would eat the flight onto its own empty surface; at its own station it swallows the empty surface too, where a zoom onto itself would be nothing). `scene_root._screen_forwards_pixel` only says WHO is asked and in what order — pit furniture (`_pit_forwards_pixel`: route cards, Rückblick, action buttons, all three visibility-gated by themselves), then Wettannahme, Automaten, Schwarzmarkt, Werkbank (its rect is `bench_rect()`, window ∪ Schürze) and finally the hub with its pages, shop included. **Physical grips on the FELT answer at their own station and in the free camera** (`CameraRig.felt_pick_live(station)`) — tray dice, discard dice, dock tiles, the treasure chips and the combo chips' upgrade pick: they lie UNDER the zoom zones, so from the RESTING overview a click on them has to stay the flight, or the gesture would eat the navigation. Grips with a window of their own (Vitrine, Ausgabefach, Kassetten-Schlitze, Magazin) need no such rule — they hang on their own visibility (`_shop_bay_rect`/`_fach_rect`/`_slit_cells_visible`). Two exceptions survive, both in `CameraRig.takes_input()`: the **title HUD is modal** (nothing behind it is touchable) and **during a camera flight everything is dead** — half transitions click badly. Right-click and the wheel keep their free-camera meaning (home, free zoom) because `zoom_out`/`_handle_zoom_wheel` know the bit themselves; the wheel is handled before any forwarding. The mouse look-around deliberately stays ALIVE while parked and eases to zero while keys are held (`_free_moving` in `CameraRig._process`), which is why the Freikamera never touches `tilt_locked`: freezing it would need a lock, and a lock would fight the drags that own that bit.
- **`CameraRig`** (`camera_rig.gd`) — the camera tilts to follow the mouse each frame **everywhere except hub, workshop and title** (`_tilt_frozen_mode()`); focused stations use the zoom angles, the overview its own. `set_tilt_locked(true)` freezes the look-around (the drag locks matter again at the tilting stations); on release it holds for `TILT_RESUME_HOLD` (0.5 s) then `smoothstep`-eases the look-around back over `TILT_RESUME_EASE` (1.0 s) rather than snapping. `release_tilt_immediately()` cuts the resume short.

### Benchmark, Stresstest & Verträge mit dem Haus
The round goal is called **Benchmark** in all UI text (never "Blind"/"Ante" — deliberately un-Balatro). Every last round of a goal block (6, 12, …) is a **Stresstest** (`GameRun.is_stress_round`), and the settlement that ends it is the **Abrechnung**. Surviving it pays a prize: `GameRun.grant_stress_reward()` rolls ONE die with a guaranteed soul and stashes it into `pending_dice`, right after `settle_block_deals` — the same `_grant_reward_die` the hub upgrade uses, so the unique/secret exclusions and the soul fallback come from one place. The ceremony is the hub-upgrade's: `scene_root._play_hub_reward_ceremony([], 0, die)` reveals the die seal over the hub and flies one comet down the workshop ader into the **Ausgabefach**, where the die rises through the tray floor. Nothing here can fizzle any more — the Magazin's cap does not reach the tray. Booked first, flown afterwards, never awaited.

**Verträge mit dem Haus are the progression system.** From round 2 on the player signs one of three contracts (`GameRun.route_offers`) — the **first round of a run deliberately has none** (`advance_round` rolls the offers, `new_run` does not), so the player throws once before the house starts bargaining. A contract is **assembled from two clause pools**: one bonus + one malus `DealClause` of the **same tier**, never a fixed pair. **No deal outlives its round**: every clause is `Scope.INSTANT` or `Scope.ROUND`, so a contract is a bet on exactly one round — the question is whether *this* round can carry the malus, not how many rounds it will bite. `Scope.BLOCK` survives as the enum's third case and in `_scope_reaches`, but no clause carries it. `active_deals` entries still stay in the list **until the Abrechnung** even though their effect is long dead: the entry locks its clause against being offered again inside the block (`_taken_this_block`). `_scope_reaches` is the single arbiter of "is this clause live"; every effect query goes through `_clause_active`, never through raw membership (bonus vs. malus is a property of the clause, so ONE query suffices).

The benchmark curve (`goal_for_round`) starts at 150 and grows by `GOAL_INCREMENT` (75) per round, doubling the step every block: 150 … 525 (R6), 675 … 1425 (R12), 1725 … 3225 (R18). The **step is the only knob** — `BASE_GOAL` stays where it is, so round 1 is unchanged and the pressure builds.

The three cards are the three tiers, left to right and **always all three from round 2 on** — **Standardvertrag / Risikovertrag / Knebelvertrag** (the Knebel is no longer gated to block 2). `TREAT_CHANCE` (30 %) turns **one** slot into a **Werbegeschenk**: the slot simply drops its `CARD_MALUS` and draws its ONE bonus out of the **normal bonus pool of its own tier** — there is no dedicated treat pool, no `also_treat` double role, and `Tier.TREAT` survives purely as the offer's *display* tier (card title and `CasinoStyle` colour). Which slot is weighted by `TREAT_TIER_WEIGHTS` (0.6 / 0.3 / 0.1), so the Standard slot usually gives the gift and the Knebel slot only rarely — `_roll_treat_slot` returns that index (−1 = none), and `_draw_card(tier, treat)` is what stamps the display tier while keeping the pool natural. Pairing is guarded four ways: bonus and malus of one card **share no tag** (otherwise the house sells zero-sum nonsense like "Auszahlung ×2 / Auszahlung ×0,5"), no clause lies out twice, no clause already signed this block, and never a second **benchmark-tagged** malus while one is active (a self-built unreachable goal is a death the player can't read — the guard is tag-based, so it covers the boss condition Hohe Erwartungen too). An exhausted pool falls back to repeats — an empty slot is worse. The Stresstest round swaps the whole offer for three of the six **Stresstest-Konditionen**: malus-only cards, so the choice is *how* you want to fight, not what you get for it.

Effects resolve **only** as `GameRun` queries dispatched on the clause id — never a silent branch in `scene_root`. `effective_goal()` inflates the stored `round_goal` (not `goal_for_round`, so a directly set goal still moves the bar) and `stage_size`/`cumulative_threshold` hang off it, which carries a benchmark clause into the bar, the overcharge stages and the win check at once. `effective_goal_for_round(n)` projects it onto the roadmap so signing visibly lifts **the station of the signing round** (no clause reaches further). Two traps the numbers impose: **money multipliers live in `add_money`** (`money_gain_factor`, positive deltas only — Happy Hour/Alles auf Rot are *all* income of the round, so they must NOT also sit in `round_payout_factor` or the payout double-dips; the one deliberate way past it is `refund_money`, the **reversal of an expense** — the Kleingedrucktes hands a pack's price back untouched, because a factored refund would turn every purchase into profit), and `charge_split(stages)` takes **stages, not charges** (the Doppellader mints two per stage) while `add_charge(count)` takes charges — the shared `_split_charge` is what keeps them from drifting.

**Four clauses turn the press's chain** (`DealClause.TAG_MULTICAST`, so the pairing guard can never sell a multicast bonus against a multicast malus on one card): **Kettentreiber** (Tier 1 bonus, Limit +2), **Zündverstärker** (Tier 2 bonus, Chance +15 %), **Zündhemmung** (Tier 2 malus, Chance −20 %) and **Kurzschluss** (Tier 2 malus, Limit ist 1). Both bonuses are quantitative and therefore carry the Winkeladvokat twice over: the factor inside `multicast_chance`/`multicast_cap` **and** the doubled prose written out in `DealClause.text_for` (+30 % / +4). All four are `Scope.ROUND`, and that reach is load-bearing: presses happen in the round's **shop**, and `round_number` only advances when the shop closes — so a clause signed at the start of round *n* is still live through *n*'s shop, and dead in the pre-commitment window of *n+1*. That is the intended window and a test pins it.

**Charms may bend the contracts, and both hooks are queries here, not in `CharmEffects`** — the effect hangs on `active_deals`/the offer roll, which only `GameRun` knows. `treat_chance()` is the single gate `_roll_treat_slot` asks (Werbetrommel ×3), and `deal_bonus_factor()` is applied **inside each individual clause query** (Winkeladvokat ×2): linear on additive amounts and on >1 multipliers, but the two *reduction* bonuses are **applied twice** rather than doubled (`pow(SHOP_DISCOUNT_FACTOR, f)`, `pow(CALIBRATION_FACTOR, f)`) — doubling "−50%" would zero the benchmark. Booleans and every malus stay untouched. Because a doubled number the player cannot read is a lie, the **card text is generated too**: `DealClause.text_for(id, factor)` holds the doubled prose written out (never computed from the base string), `active_deal_sides()` ships the finished line in the side dict and `RouteChoiceView.open` takes the factor as a parameter — so both views keep knowing nothing about `GameRun`. A new quantitative bonus clause therefore needs its factor in its query **and** its doubled line in `text_for`.

**Throttling** is no longer automatic in the Stresstest; it comes only from clauses. `hottest_combos(n)` picks deterministically at round start (level desc, tie → higher `HAND_PRIORITY`; `ONE_KIND` never, it's the fallback every hand must keep — and the tie must be broken *explicitly*, `sort_custom` is not stable) and only the Hitzewarnung uses it. The boss conditions Allrounder/Standardprotokoll make the list **grow mid-round**: `note_hand_taken(key)` is called from `scene_root._apply_hand_clauses` after every take and can lock even `ONE_KIND` — a throw with nothing scorable is then a farkle, by design. The list travels as `DiceScoring.CTX_THROTTLED` inside the same ctx every scoring call already gets, so preview, take and farkle comparison agree; `best_hand` falls through to the next matching category. The chip shows it itself (`ComboChipView.set_throttled` = red band + "AUS"). Because the boss condition is signed *before* the round, `apply_round_start_charms` sees it — that order is load-bearing.

**Parität (Schieflage/Gleichgewicht)** rides the same ctx (`DiceScoring.CTX_PARITY`) but bites **before** detection: `legal_indices` filters the dice, `qualifies`/`participating_indices` run on the filtered list and map the indices back, and the Vollzähler is intersected with the legal set. **No essence is exempt** — `legal_indices` knows nothing but the parity, and the old Krypton escape hatch (`EssenceEffects.ignores_dice_filters`) is gone: a soul may widen what counts, never unlock what a clause barred. Consequences that must not be undone: `ONE_KIND` now qualifies only when a legal die exists (so an all-even throw under "nur ungerade" scores 0 and farkles), and `participating_indices` must keep returning REAL slots or materials and die-bound charms fire on the wrong die.

**Where it shows.** The choice lies **in the pit** (`RouteChoiceView`, a child of `TableScreen` spanning the pit's upper part above the net field — `scene_root._place_route_choice`); the card shows the **tier name** as its title (plus a decorative "§ N"), then the bonus clause (green) and the malus clause (red) — each is just its **effect text**, no clause name, no heading and no duration label (the card was too crowded; green/red carries the bonus/malus split, and the duration lives on the deal tokens as their size), tinted by `CasinoStyle.contract_tier_color`. Signing reports the **slot index**, not an id — a card is two clauses, so only its position identifies it. The round starts normally, and the cards appear the first time the player focuses the pit that round (`_on_camera_mode_changed`, same hook as the supply tray), i.e. right before the first throw. No close button, but **the pit may be left**: right-click and every zoom zone work as usual, the cards are pit furniture and go with the rest when the camera leaves (`_sync_screen_action_buttons` closes them), and the next pit focus lays them out again. Only the **throw** is gated (`route_pending`) — the player may look around the table before signing, but cannot start the round. Consequence of the re-entry: the decorative "§ N" is **derived from the clause ids** (`_section_for`), never rolled, or it would change every time the player comes back. The cards take the **whole pit floor**, so the pit's own furniture (action buttons, net field, material hint, both score orbs) hides while they show — driven from `_sync_screen_action_buttons`, which runs per frame and therefore also takes back what `update_pit_score`/`_refresh_ui` switch on in passing. The cards are the pit's own forwarding case (`_pit_forwards_pixel`), next to the Rückblick and the action buttons — they carry their own visibility, so nothing else needs a mode. Because the round now starts *before* the signature, the round-start effects are split out into `_apply_round_start_effects` and fire either immediately (round 1, no offers) or on signing — the boss condition must be known before the throttle is computed. The view's unit derives from **both** axes (`min(w/100, h/46)`); the pit is wide and flat, so width alone would produce giant type. Active sides live on as **tokens**, and the row is **mirrored**: one `DealTokenRow` under the hub's rim and a second along the pit's upper edge, both fed the same `GameRun.active_deal_sides()` from one place (`scene_root._refresh_deal_tokens`) so they can never disagree. Grammar (owned by `DealTokenRow`, not by either host): fill = the clause's **tag** color (same theme, same hue at a glance), ring green/red = bonus/malus, size = duration (the code still ranks BLOCK above ROUND, but with no BLOCK clause left every live token is the same size), glyph +/−; hover opens a `HintCard` — the shared card the Stresstest station uses too, which must be a child of its stage because it positions itself stage-relative. Rebuilt whole, never patched. **Every round end** sweeps both rows (`scene_root._sweep_deal_tokens` → `sweep_deal_tokens`/`sweep_pit_deal_tokens`, the longer awaited before the shop), because the clauses die with the round; the Abrechnung after a Stresstest then only clears the id locks (`settle_block_deals`) and must not sweep a second time.

Two rules the pit row lives by. It sits at the pit's top edge **left of center**, because the score window's data ader drops into the pit dead center — a token on that lane gets crossed by every scoring comet (`PIT_DEAL_RAIL_*`, world coords like the other pit furniture; its `u` comes from the strip height so the largest token fills it to 80 %). And its hover cannot use `mouse_entered`: the pointer is on the table, not in the `SubViewport`, and outside the forwarded rects no motion ever reaches the marks — so `scene_root._sync_pit_deal_hint` asks `pit_deal_token_at(pixel)` per frame (hence `self_hover = false` there), which also means the row comes and goes with the rest of the pit furniture in `_sync_screen_action_buttons`. Roadmap markers now only ever mark the Stresstest station, tinting the **bubble itself** — a dot under the disc was invisible from the overview distance, and marked stations deliberately ignore the distance fade (the Stresstest always sits farthest).

**`DealClause.find` hands out ONE shared instance per id** (a static `_by_id` table built on first use), because `all()` allocates 48 fresh Resources and the overcharge stages ask through `_clause_active` dozens of times *per frame* — that alone cost ~5 ms per `stages_cleared` call at high scores. Every caller only reads a clause; never mutate one you got from `find`.

A new clause gets its id + factory + `all()` entry in `DealClause` (tier, scope, tags — the tags ARE the pairing rule, an untagged clause pairs with anything) and its effect as a `GameRun` query; a new *effect kind* also needs its call site (payout, goal, side bet, overcharge, shop price, per-hand, per-farkle) wired through the matching query. Clause-only, per-hand effects hang in `scene_root._apply_hand_clauses` — one place, so grants and the growing throttle can never fire in different orders. **Money losses are not among them: a fee pays at its trigger.** The per-HAND costs (Servicegebühr `hand_fee`, and `tax_side_bets` with both its stake kinds — its void logic stays one atomic call inside `GameRun`) book at the moment the hand is banked, right before `_play_take_animation` starts; the per-DIE cost (Abzocke `scored_die_fee`) books one payment per counted die inside the die-step loop, next to `_pay_street_musician` (`_pay_die_fees`, clamped at the wallet per booking). A charm fee sits neither place: the Schutzgeld's flat $3 rides its OWN charm step (`CharmEffects.charm_fee_at` → the step's `"fee"`), so the pad flashes and the money leaves in the same moment, and base, mult and total stay untouched. So the spend animation runs where the event is, and with a low wallet the clamp bites at the trigger instead of after the fact.

### Energie (⚡) & Schwarzmarkt
(The player-facing word for the resource is **Energie** — every UI text that names it in words says "Energie"; the ⚡ glyph stays as the compact symbol in numeric labels, and the code keeps `charge`/`add_charge`/`charge_cap`. "Überladung"/"Überladungs-Stufe" is a different word: the stage mechanic.)

**Every ⚡ the player GAINS travels to the capacitor bank as a comet** — there are exactly five sources and all five do it: the payout's cleared stages (`_play_bank_discharge`, which also books on arrival), the instant deal clauses (Startkapital & Co., `GameRun.instant_clause_charge` — the single source for both the booking and the ceremony), a won ⚡ side bet (`SideBet.Payout.CHARGE`, booked in `resolve_side_bets`) the **Funkenflug** rune (`RuneEffects.charge_for_take`, collected in the `TakeReport` and booked in the take — once per Zug per face, never per activation) and the **Dynamo** charm, which pays at the end of every CLEARED round from its seat in the round-end charm ceremony (`CharmEffects.round_end_charge_at`, one step per dock position). Clause, side-bet and Funkenflug charges are already booked when the ceremony starts, so `scene_root._play_deal_charge_volley`/`_play_side_bet_charge_volley`/`_play_rune_charge_volley` are **visual only** (`_fly_charge_to_capacitor(false)`) and must never book again — **book first, fly afterwards** is the pattern for every new source; both ride the same two legs as the payout (into the hub, then the hub-cluster ader to the bank), dense-staggered like the Frankiermaschine volley and guarded by comparing the run instance. Only leg 1 differs — the side bet leaves through its own window ader. Spending ⚡ (Discharge, purchases, rerolls, **Übertakten**, the **Automaten-Einsatz**, the **Tscherenkow-Krit** - the Schwarzmarkt entry is no longer one of them, and die Presse presst gratis) is a loss and animates differently or not at all. The Tscherenkow is the one sink inside a hand: each of its crit slams is ×8 and burns 1 ⚡, so a running remainder is threaded through both mirrored walks (`DiceScoring._base_and_mult` and `ScoreBreakdown.build`) exactly like `running_values`, the breakdown reports the sum as `charge_spent`, and the take books it (`TakeReport.charge_spent`, `spend_charge`) where it books the Funkenflug gain. The Steuerstab charm makes the slam free and swaps the fixed factor for ×(stored ⚡). `SlotPrize.Kind` has no charge kind — the slot machine pays only in goods, and it is **bought** with ⚡: a spin costs `SlotMachine.SPIN_CHARGES` = **1 ⚡ at every one of the three machines** (`GameRun.slot_spin_charge`, 0 while a Freispiel stands; `can_spin_slot` measures against `charge`, `spin_slot` calls `spend_charge`), because the machine's Stufe decides the prize, not the price. The stake light is therefore ONE leg, the Schwarzmarkt's grammar rather than the money's two: `scene_root._on_slot_spin_paid` sends `slot_pay_comet(CasinoStyle.CHARGE)` hub → Automaten against the ader's laid direction, and `SlotBankView.coin_travel_time` is just `slot_pay_travel_time()` — the reel starts when it lands. `_on_charge_changed` re-asks the window (`refresh_if_idle`), so the Drehen button dims and wakes with the bank.

**Übertakten is the ⚡ sink on the felt (die Presse is none any more: one free pressing per session, see *Die Presse*).** A combination's next level costs `GameRun.overclock_cost_at(level)` = `min(1 + level, 5)` ⚡ — the same ladder for every combination, capped at 5, with **no level cap**: the wallet is the only brake. Flat like every ⚡ price, so `shop_price` and its clauses (Inflation/Skonto) deliberately do **not** apply; `overclock_combo` is check-then-spend like `buy_secret_offer` and returns `false` untouched when the bank is short. It is buyable **whenever the player can reach the combinations zoom**, mid-round included — no phase gate. The ceremony is pure display: booking is synchronous inside `overclock_combo`, so `_on_combo_upgraded` refreshes the cell **immediately** and only then flies the cyan pulse (never awaited by the caller) — which is what makes rapid clicking safe without a queue. It must skip the celebration when the level *dropped* (Hitzestau emits the same signal downwards). Level growth itself is authored per category (`points_step`/`mult_step` in `DiceScoring.CATEGORIES`), never the base value re-added — the old `base × (1+level)` grew the fixed product quadratically and made the top hands run away from the bottom ones by two orders of magnitude.

The overcharge **frame is 5 from hub level 1** (`GameRun.overcharge_frame`) — it is no longer a hub reward, only clauses move it (`max_overcharge_stages` still layers them on top). Cleared overcharge stages pay **no money**: each mints one **Energie** into a capped wallet (`GameRun.charge`; `charge_cap()` = `charge_cap_rows() * CHARGE_ROW`, i.e. 5/10/15/20/25 at hub levels 1/3/5/7/10 — the cap only ever moves in **whole rows of 5** so a hub upgrade reads as "one row wakes up", never as a crooked number). Money comes **once** for the cleared benchmark (`MONEY_PER_ROUND_CLEAR`) — and again per stage that no longer fits. `charge_split(stages)` computes that split as a **pure preview**, planned *before any booking*; the booking itself happens stage by stage in `scene_root._play_bank_discharge`, **exactly one comet per cleared STAGE** on the existing bank route (cyan = ⚡ into the wallet, gold = overflow as money). **GameRun computes, the ceremony books** — never the other way round. The Doppellader therefore does **not** double the meteors, it doubles what one carries: the arrival books `charge_per_stage()` charges at once (`_fly_charge_to_capacitor(book, amount)`), because twice as many impacts would read as twice as many cleared stages. The split stays the arbiter — the charges are handed out in order, so a single stage can arrive **divided** (part ⚡, the rest cash at `base_blind` per charge) exactly where the wallet fills up mid-stage, and the sum of the bookings is byte-identical to the planned `stored`. The comet carries no "×2" of its own: the payout line already names the total, and a second number on a route this short fought the read.

Its rect (`_secret_shop_rect`): right edge flush with the slot column, bottom flush with the hub, width from the height via `SECRET_SHOP_ASPECT` (1.8, capped at the column). That aspect is **authored on the number the glass used to produce** — the ellipse once cut the left edge, and when it went away the value was frozen rather than freed, because everything below hangs on it. The result is small and flat (~450×250 **texture** px, the smallest window on the table), and that number — not the visual impression — is what its zoom and its type are solved against. **A window is never magnified past its own texture resolution**: at the old `SECRET_SHOP_ZOOM_DISTANCE_CUT` of 11 its 451 texture px covered ~780 screen px, i.e. 0.58 texture px per screen px — a 1.7× upscale that read as "360p". The cut is 4, so 451 texture px land on ~440 screen px (~1.0). Raising `TableScreen.SUPERSAMPLE` is not the answer: it multiplies the whole 1560×1060 viewport, measured 3 → 4 takes the frame from 35 to 58 ms and still only reaches 0.77 tex/px. For reference the slot bank sits at 1.28 tex/px — no window can beat it without a bigger rect. Reveal and reroll drive the **same Hebebühnen-Zyklus** as the shop, and here BOTH zones live inside the one `VitrineView`: Regal first, Schale `ZONE_LAG` later, mirrored on the dive. `CapacitorBankView` is the physical ⚡ wallet — pure display, it never touches `GameRun`: a **fixed 5×5 grid**, all 25 cells present from run start, in three states — dark (row still locked), faintly **cyan** glimming (awake, empty) and a hot **amber** lamp, breathing on its own per-cell phase (an Energie stored). Amber is deliberately a different hue from `CasinoStyle.CHARGE` (the shared cyan) so a stored point can't be mistaken for the empty-but-awake glim, and its brightness is capped just over 1 in red: pushed higher it **clips to flat yellow and adjacent charged cells merge into one bar**, which destroys the countability the whole grid exists for. `_process` runs only while charge > 0. A cap change is therefore a **restyle, never a rebuild**: the upgrade moment is "a row wakes up". It stands **in the chip grid**, on the free slot at the cluster's bottom right (`TableScreen.free_cluster_slots()` derives the empty raster positions from the real cells, so a cluster rebuild carries it along), and **fills** it — but a single cell (~3.16:1) is a flat strip, so `scene_root` **stretches the slot ~2× downward into the bare felt below the cluster** (`CAPACITOR_SLOT_TALL`, top edge pinned to the chip row; the pit sits to the *right*, not below, and the glass runs far down there) to a ~1.58:1 target. The footprint's aspect is trimmed to just under *that* stretched slot (`max_width()/max_length()` ≈ 186/294) and `scene_root` fits the **tighter of both axes** (`CAPACITOR_SLOT_FILL` 0.97), so grid and slot agree on both axes at once (~97 %, components ~94/92 %) instead of leaving the extra height as bare felt. Note `pixel_to_world` swaps the axes — slot **width** (pixel x) becomes world **z**, the grid's long axis. Each cell is a **liegender Radial-Elko**: a dark can along that long axis, a dark crimp ring on its leg-end face and two tinned wire legs angling down onto the base plate — which is what turns the plate into a Platine. **Lying, not standing**, because the table looks nearly straight down and a standing can would show only its lid. Can length ≈1.5× diameter, can + legs = 0.9 of the column pitch. The three states sit on the **can alone** (the cell root's `material_override`); ring and legs are children sharing one mesh and one static material across all 25. Two traps the form imposes: the ring must stand a hair **proud** (`CRIMP_PROUD`) or its face and the can's cap fight over the depth and fray into a flicker pattern up close, and it must sit **flush** on the leg-end face — set inwards, the can's tail past it reads from the overview as a second lit blob and every charged cell counts twice. The **row gap is the expensive number** — a row is only a few screen pixels tall, so too tight a seam melts the rows into solid bands; `ROW_PITCH − CRIMP_DIAMETER` (the ring is the widest part) is what holds it open. It sits on bare felt, where there is no glass, so it is deliberately **not** reflection-marked. It lies flat in XZ — the overview looks nearly straight down, and rows of 5 stay countable at the zoom distances. Emission only, no per-cell lights (the tiled ground has a 16-light budget). `pulse()` pops around the **resting** scale captured at pulse time — tweening to `Vector3.ONE` would permanently inflate the caller-scaled bank past its slot. The payout's ⚡ comet is therefore **two legs**: goal bar → hub (the existing bank route), then hub → capacitor along the **hub-cluster ader** (`charge_comet`), at whose entry corner the bank happens to stand. Leg 2 is deliberately *not* awaited — the next stage launches immediately, Frankiermaschine-volley style — and the booking (`add_charge(1)` + both pulses) happens on **leg-2 arrival**, guarded by `phase == Phase.PAYOUT`. Spending doesn't animate; the bank just resyncs from `charge_changed`.

Its seat exists from the moment the house carries specials at all, empty roll or not — the row hangs on the licence, not on the Auslage. Bought it goes **sealed** into `owned_packs` through the normal `purchase_pack` (Kleingedrucktes and refund comet included). ### Extending content
A new **charm**, **engraving**, **essence** or **rune** needs no registration map: add a factory method + `all()` entry in the `data/` class and its effect in the matching `core/` effects class, both wired by the same id constant. Three charms died with the edge purge and must not come back by accident — **Rahmenvergolder** (it became a byte-for-byte duplicate of Goldschmied), **Magnetring** and **Zargenglanz** (no targets left); two more died with the Veredelung, which left no ladder to climb — **Politur** and **Gießkanne**; the **Gravierstift** died with the Verbrauchs-Haushalt (nothing is consumed any more); three more died with their souls in the Essenz-Rework — **Sumpflaterne** (Irrlicht), **Sonnenfinsternis** (Korona) and **Druckerpresse** (Ethylen), and the three essences `will_o_wisp`/`corona`/`ethylene` went with them. Careful with the Politur: the *etching* `Engraving.POLISH` ("+1 auf alle Seiten") shares the id string `"polish"` and lives on. **Asset filename = content id** (`assets/models/<charm_id>.glb`, `assets/textures/engravings/<engraving_id>.jpg`); paths are derived by convention. `DieDefinition` is shared by reference — call `instantiate()` before mutating a die you take ownership of, or a later upgrade mutates every die sharing that definition. **`Engraving.Rarity` drives exactly two things**: display (`rarity_name`, `EngravingRenderer.SEAM_COLORS` — the Lichtsaum) and the press's **icon weights** (`RARITY_WEIGHTS`/`weight_of`, consumed by `PhantomPress.weights_for`) — so a rarity edit moves both the odds and the Ablage's order at once. The old floors and single prices died with the Presse; strength still comes from the hand, quantity from the Multicast, never from the rarity.

**Essenz-Charms hängen an ihrer Seele.** Every essence from `Rarity.RARE` upwards has exactly **one** charm that sharpens it, and the pairing lives in one table: `Charm.ESSENCE_REQUIREMENT` (charm id → essence id). That table is also the **offer rule** — `Charm.offerable(pool, owned_essence_ids)` is the single gate the shop spread, the Schwarzmarkt charm slot and the slot-machine prize all pass through, so a charm never lies out while its die does not exist (twenty dead cards would dilute an 83-charm pot by a quarter). The charm reads the **effect, not the die**: a Quintessenz that borrows Ozon also borrows the Gewitterfront, because every hook takes `charm_ids` next to the already-resolved essence set. The Quecksilberlampe charm deliberately stays **out** of the table — it belongs to every activation factor, not to one soul. Adding a new essence ≥ RARE therefore means adding its charm too; a test asserts the two lists stay in step.

**A pool entry is never swapped, only overwritten** (`DieDefinition.become`): the round deck, both trays and the workbench grid all hold the *same* instance as `owned_pool[i]`, so a purchase that replaced the instance left every one of them on the old die. `_replace_pool_entry` (slot-machine die) and `exchange_pending_die` (the Ausgabefach's Tausch — the ONE way a bought or won die reaches the pool) therefore write **into** the entry — and every change to a pool die reports it through the single signal `GameRun.pool_changed`: the in-GameRun mutators emit it themselves, outside mutators (engraving station, `MaterialEffects.apply_take_effects`) call `note_pool_changed()`. `scene_root._on_pool_changed` is the one refresh path (three trays + `DiceController.refresh_faces` for the dice lying in the pit + the open station); never patch a single view after a mutation.

**Replacement vs. arrangement.** That rule governs *replacement* only. `GameRun.reorder_pool(from, to)` **moves ONE die**: it is taken out at `from` and inserted at `to`, and everything between rides one place along — deliberately not a swap, so a die lands exactly where it was dropped and the row closes behind it (the same `remove_at`/`insert` the queue tray's `_animate_reorder_move` has always used; a swap would fling the drop target back to the source slot). The instances travel to their new slots with their identity intact and their contents are never rewritten, which is exactly why instance-keyed state (Phosphoreszenz's base and mult stores, the Abguss marks, all keyed by `get_instance_id()`) stays attached to the right die for free. `become` = a die's contents change; `reorder_pool` = a die's *place* changes. **The deck is the pool until the round is signed**: `_start_new_round` copies `owned_pool` unshuffled and `_on_pool_changed` re-copies it while the round is still open, so the whole bench window shows the dice where the player put them; `scene_root._commit_round` (the signature, or the first throw in a round without offers) is what shuffles — once, idempotently — and only then does the Frische-Ware partition pull its group forward again (`_essences_first`: the group is the **beseelten** dice, `essence_id != ""`, never the material carriers). Arranging before the round is therefore *reading* strategy, not draw-order strategy, and a queue-tray reorder made before the signature does not survive it. Reordering rides the same window as engraving (`_dice_editing_locked()` false: pre-signature bench time and the shop), and reaches `reorder_pool` from two places — dragging a die onto another in the pool tray (`DiceTrayView.SLOT_PICK_LAYER`, the one hit path) and dragging tile onto tile in the DOSSIER's grid (the Paket-Platzierung was the old second place; the dossier inherited it, and the tap/drag split keeps the two gestures apart). Everywhere the split is the same and needs no arbitration: **dragged rearranges, tapped selects** — a `Button` only emits `pressed` when the release lands on itself, so the reorder and the pick can never both fire. The tray drag therefore also runs **while a Platzierung stands** (only `REORDER_DRAG_THRESHOLD` decides which gesture it was); the press is not a modal state for the trays. The pool tray drag is the queue tray's gesture exactly: the die leaves its slot, a `_spawn_deck_ghost` follows the pointer, and on drop every affected slot becomes a ghost that glides to its new place (`_animate_tray_reorder`, shared `_queue_index_after_move`). Two rules hold it together: the ghosts are registered **before** `reorder_pool` is called, because their presence is what makes the `pool_changed` refresh stand down until the animation ends; and the refill goes through `_refresh_dice_trays`, which picks the source by phase — in the shop the whole pool lies in the tray (`_return_dice_to_pool_tray`), otherwise it is the round deck. `DiceGridView.reorder_enabled` is **off by default**: the Ausgabefach's exchange picker is the same class in a different role and must stay a pure pick target — only the dossier switches it on.

### Hand choice & Farkle (fixed rule)
`DiceScoring.best_hand` walks `HAND_PRIORITY` top-down and takes the **first** category that qualifies and isn't throttled — there is **no score comparison across categories**. What physically lies on the table wins, however many points a lower-ranked chip would pay (three Zweierpäsche are never taken as a leveled-up Zwei Paare). Consequence: the throttle fall-through still works (a locked category is skipped, the hand slides one rank down).

**Straßen laufen auf dem Ziffernring 0-9.** A straight of length L is L consecutive positions on the *cyclic* ring of Kombinationsziffern (`_digit` = `value % 10`) — start anywhere, wrap through the 0 allowed, so 8,9,10,21,22,23 (digits 8,9,0,1,2,3) is a large straight and the classic 1-6 straights are unchanged. Digit 0 is a full citizen; beyond 1-6 the ring is only reachable via engraved or grown faces, which is the point. The **Zahnlücke** charm is the one charm that reaches into *detection*: with it, L distinct digits inside a window of L+1 ring positions qualify — exactly one hole. The plain window always wins over the holed one, the rule itself lives in `CharmEffects.straight_gap_allowed`, and `charm_ids` therefore rides through the whole detection chain (`qualifies`/`_qualifies_plain`/`_has_straight_of_length`/`_indices_for_straight`/`_participating_unsorted`/`wild_value`).

The **Farkle rule is the same measure**: `is_strictly_better` compares only the `HAND_PRIORITY` **rank** of the two picked hands (`hand_rank`, smaller = higher) — **points never decide**. A reroll is safe iff it lands a strictly higher rank; the same rank farkles even with far more eyes (pair of 2s → pair of 6s), a lower rank farkles, and 3er-Pasch → 4er-Pasch can never farkle. Materials, edge materials and combo levels stay in the signature (they belong to the hand) but no longer influence the verdict; the **throttle in the ctx still does**, because it decides *which* category `best_hand` picks. A hand that scores nothing at all (parity/throttle) is never progress.

**The last dice are played out.** The round only ends automatically on a full overcharge, the hand cap, or an **empty** pool (`_round_should_end`) — a leftover of 1-5 dice is thrown as a smaller hand (the draw loop already stops at the pool's end). Consequences: `DiceController.set_slot_defs` pads the unused slots (every slot query runs over `count()`), detection runs over the **lying** dice only (`_auto_select_best_combo` goes through `_pit_combination_slots`, or the empty slots' zeros would form their own Pasch), and a hand that can neither be taken nor rerolled is a **Fumble**, not a dead end — `_on_farkle(false)` then skips the forgiving charms/clauses, which would only leave the hand unplayable. Leftover-dice payouts (Sparprämie & Co.) therefore only come from banking early; playing the rest out is the player's choice.

### Scoring trigger order (fixed — NO exceptions)
**Transform charms run first and are ONE ascending chain** (`CharmEffects.transform_value`): 1→6, 2→3, 3→4, 4→5, 5→6, 7/9→8. Ascending by design, so the chain keeps climbing — a 2 reaches the 6 with all four link charms owned — and every result (6 or 8) falls outside the trigger values, which keeps the chain idempotent. The Achterknoten is the only one coming from above (engraved faces climb past 6), and because detection uses `value % 10` it moves the Kombinationsziffer too — that IS the charm. The pit shows the effective value **on the die**: `DiceController.set_value_overrides` paints the up face's number in `DieFaceDisplay.PREVIEW_NUMBER_COLOR` (the same green as the workbench engraving preview — green means "not in the def" everywhere), driven from `scene_root._sync_transform_previews` on every `_refresh_ui`/`pool_changed` and silent during `Phase.SCORING`, where the running value owns the number instead. Display only: `values` stays what the scoring read. The charm side ends in `CharmEffects.shown_by_charms` — chain first, then the Schutzgeld offset (+10 per copy, deliberately a multiple of ten so the Kombinationsziffer stays put), which is a **separate step precisely because it is not idempotent** and must run once per face; the **essence lens runs right after it** and `DiceScoring.shown_value(raw, charms, essences)` is the one function that answers "what does this die show". The preview calls it, not `transform_value`, and `MaterialEffects` asks `shown_by_charms` wherever the take counts face triggers, or simulation and def would disagree on how often a face fired.

There are **two charm classes**, and the class decides *when* a charm fires:

- **Die-bound charms** (`CharmEffects.die_charm_*` hooks) hang on a concrete die and fire **with that die** in the die phase — Mehrfachstecker/Straßenbesen/Bodensatz/Prime Time/Kleinvieh per combination die, Hochstapler with the highest scored die (`die_charm_target_mult_at`), Quadratur with the lowest. `die_charm_crit_at` currently carries **no** charm (Beherit moved to the static crits) and survives as the stage for the next die-bound crit. When a die fires more than once (Argon & Co., Hasenpfote, Echo-Kammer, Nachglühen — `MaterialEffects.die_trigger_count` × `face_trigger_count`), its die-bound charms fire **once per firing**, interleaved: Würfel → Charm-Anteil → Krit-Schlag, then the next firing. Within one firing: eyes → material (`MaterialEffects.*_once`) → die-bound additives → die-bound crits.
- A charm that writes **permanent face values after the hand** is neither: it is a step in `MaterialEffects.apply_take_effects`, and it belongs at the **end of the tail** — after bone/glass, the Miasma spread, Kontrastmittel and the Radon decay, so it sees final values and nothing overwrites it, and before the Streulicht loop, which only reads unscored dice. The Gleichrichter is the reference (`_rectify_faces`): protection (`value_protected`) blocks only the **shrink**, a protected die still counts into the mean, and every touched slot goes into `report.grown`/`shrunk`, which is what buys the flares and `note_pool_changed` for free — no scene_root change at all. Nothing here may touch the scoring simulation; the count is over.
- A charm whose effect depends on **what the hand counted before it** is neither, because the `die_charm_*` hooks are stateless: it needs an accumulator threaded through **both** `_base_and_mult` and `ScoreBreakdown.build`. The Wasserfall is the reference (`CharmEffects.cascade_mult` + a `cascade_last` running through the die loop, links included); its contribution rides in the firing's `charm_mult_add` with its dock index merged into `die_charm_indices`, so the pad still flashes at the right moment. The **combination** is the other exception: `CharmEffects.combo_factor` (Dreifacher Boden, ×3 per copy) scales the combination's **base points only** — `points_for` at the call site, never `mult_for`, and both functions keep printing the pure level for chips, overclock prices and previews.
- **Static charms** (`charm_*_at` hooks) depend on the hand/state, not on a single die. They fire **after all dice, strictly in ownership (dock) order** — additive bonuses AND crits (Einserkult, Snake Eyes, Zwillingsring, Feierabendbier, Galgenhumor, Beherit) apply at their exact position, never pooled at the end, so dock order is gameplay-relevant. The Vorreiter is one of them too — `charm_base_bonus_at` hands it the eye sum of **all lying dice**, once. **Static crits** multiply the *current* mult (`charm_crit_at`, `crit_x` on the charm step) — that hook is the only factor left in the charm phase, and Snake Eyes clamps its ×Augensumme at 1.0 so a sum of 0 or 1 is no crit at all. There is no total-level phase any more: `charm_total_factor_at` died with the old Zauberkarte, and `post_steps` survives as an empty stage in the breakdown.

**Die-phase order is the lined-up row and is scoring-relevant.** The sweep iterates `DiceScoring.trigger_order(scored, dice, declared, participating)`, and the rule is **combination-first**: the combination dice form blocks by Kombinationsziffer, the blocks stand by **size desc, then digit desc**, inside a block by shown value desc and tie → smallest slot; the merely counted dice (Vollzähler, Krypton) fall in behind by the same value/slot rule. A group therefore stays together — a Full House counts 3-3-3-5-5, never 5-5-3-3-3, and a straight reads 6, 5, 14, 13, 2. Without a `participating` list (older callers) there are no blocks and the plain value order remains. `_line_up_settled_dice` does not re-implement any of it: it CALLS `trigger_order` with the selection as the combination, so row and count can never drift. Those values are the **shown** ones everywhere: `hand_shape` feeds `trigger_order` its `shown_values`, and on the table side `scene_root._shown_pit_values()` is the single answer the physical lineup, the take's `trigger_order` and the Flickenteppich's `target_die` all ask — a raw 3 that Fuchsschwanz turns into a 4 lines up, targets and pays as a 4. Because a material or essence ×-crit books inside the die phase, this order *changes totals* by design (mult added after the crit die's step escapes the ×), and the Wasserfall, the Stroboskop and the Miasma spread all read it as a sequence — that's why the order must stay canonical; never derive it from physical positions. `participating_indices` still returns slot-sorted indices; "der zuerst gewertete Würfel" (Echo-Kammer) means the **head of that row** — `hand_shape`'s `echo_slot` is `order[0]`, so a declared arrangement moves it.

**The running value (Knochen/Glas between activations).** When a die fires more than once, bone growth and glass shrink happen **between** the countings — the second activation counts the grown (or shrunken) value. `_base_and_mult` keeps the running values of the **whole hand** (`running_values`, seeded from `raw`) and mutates the firing die's entry after every activation via `MaterialEffects.mutate_value_once`, the **same helper** `apply_take_effects` writes into the defs, so the simulation and the permanent face can never drift (asserted by a test battery over bone/glass/glue/marrow/veredelt × 1-3 activations). The array is hand-wide, not per die, because **Miasma und Radon spread across dice at every firing**: right after the mutation `MaterialEffects.spread_miasma_once` hands the source's halved eyes to every OTHER scored slot, so a die later in the row counts the grown number, the source's own next firing counts its halved one, and with the Weihrauchfass (no self-loss) the same amount goes out every time. It fires on **up-face firings only** — never on a Pointer link or a deterministic one, a link being another face; Stickstoff/Einbrand (`MaterialEffects.value_protected`) block the halving and then nobody gets anything. Radon is the **positive twin** (`spread_radon_once`, right behind the Miasma in every one of the three walks): its firing grows the up faces of all OTHER counted dice permanently by +2 (Bleischürze +3) — a GAIN, so no protection blocks it, and the source gives nothing away. The old silent `foreign_eye_bonus` in the eye sum is gone; the eyes really move now. `ScoreBreakdown.build` mirrors the identical walk, and `apply_take_effects` runs the same spread on the defs — which is exactly why its value-mutation walk iterates in **trigger order** (`_take_order`, the `order` param; a caller without one falls back to slot order) and why the retrigger values are frozen into `_charm_values` before the first mutation: a cross-die spread makes iteration order and mid-walk face reads scoring-relevant, where every other die-local effect was indifferent to both. Three boundaries are load-bearing: the mutation rides the **physical** value (`raw`, the untransformed faces — `score_category` keeps it, `best_hand` therefore passes RAW dice down and only detects on transformed ones), so a transform charm stays a lens and the run ends where the def ends; **eyes, the die's own material math and the AMOUNTS of the die-bound charms** follow the running value (`value_override` = the firing's `shown`, so the Hochstapler adds +4 then +6 on a growing bone face), while `trigger_order`, hand detection, `participating`/`scored` and every charm hook's **targeting** (`target_die`, the row head) stay pinned to the settled **shown** values — charm transform chain plus essence lens applied, never the raw faces and never the mid-count running value: a count must never reorder or retarget itself mid-play, and a transformed die is a transformed die for every purpose but the def; and **Pointer links keep their stored values**, a link being a different face. `ScoreBreakdown` mirrors it and gives each activation entry `value` (what it counted) and `value_after` (the physical value after the mutation), which is what `scene_root._play_die_pulse` switches the die's number to between pulses — in the NORMAL color, because the change is permanent, and the def carries the same number once `apply_take_effects` has run after the ceremony.

**Ties on a single-die charm (fixed rule).** When a charm means exactly *one* die picked by its face value (Hochstapler = highest, Beherit = lowest, Flickenteppich = highest), a tie is broken by **the first matching die — the smallest slot**. Never scan for the extreme value yourself; call `CharmEffects.target_die(values, candidates, highest)`, the single source of truth — and hand it the **shown** values, so a raw 3 and a natural 4 tie under Fuchsschwanz and the smallest slot wins.

**Zwei Auslöse-Achsen (fixed).** How often a die's up face fires is **die_triggers × face_triggers** (`MaterialEffects.die_trigger_count` × `face_trigger_count`, product in `total_trigger_count`). Each axis is internally **additive**, the two **multiply**, and there is no third axis. Nothing CAPS them any more either — the Sternschnuppe fires like every other die and only its ×4 crit is rationed (once per round, at the very first firing of its first scoring; the Meteorit moves that to the first firing of EVERY scoring). The **Würfel-Achse** = essence factor (the only factor anywhere) + Echo-Kammer copies on `echo_slot` + Sauerstoff/Sonnenwind order extras + Sechserpack copies once the hand uses all six dice (`CharmEffects.full_hand_retriggers`, fed by the `scored_count` param that **every** `die_trigger_count`/`total_trigger_count` call site must pass — the scored set's size, `order.size()` where the caller has the row) + Zauberkarte copies on the **combination dice** of the round's **first taken hand** (`CharmEffects.first_hand_retriggers`, which owns BOTH conditions so no call site half-rebuilds the rule; the two facts travel as `is_first_hand`/`in_combination` on `die_trigger_count`, derived from the ctx's `CTX_HANDS_TAKEN == 0` and from `participating` — not from `scored`, so a die that only the Vollzähler or Krypton pulls into the count gets nothing. `apply_take_effects` therefore takes a separate `combination` array next to its (scored) `participating`, empty = the two are the same, which is what keeps simulation, take, pointer roll and gold pre-pass byte-identical); the **Seiten-Achse** = 1 + Nachglühen runes + the retrigger charms (Hasenpfote 6 / Kleeblatt 4, on the *transformed* value). So Quecksilberdampf × Nachglühen is 6 firings, not 4. `DiceScoring._base_and_mult` runs them nested (outer die trigger, inner face trigger); each inner iteration is one full firing — eyes → material → die-bound charms → crits → `MaterialEffects.mutate_value_once` on the running value. `apply_take_effects` iterates the SAME nesting, which is what keeps simulation and permanent def byte-identical.

**Pointer.** The die-wiring mechanic, named **Pointer** in UI text and comments since 2026-08-13 (it was "Leiterbahn"; the table's LED adern keep that word for their PCB look). `DieDefinition.pointers` lets each face point at ONE adjacent face (`can_point`; opposite = `5 − i`, calibrated to `AXIS_FACE_INDEX`) — the def carries only the wiring (`pointer_target`), never a chain. A pointer is a **chance**, and the chance is the whole mechanic: after the face-trigger batch of **each** die trigger, one invisible roll at the aggregated `1 − (1−p)^face_triggers` (`DiceScoring.pointer_chance_for`, base `POINTER_CHANCE` = 0.5; Plasma gives the roll a **second shot** via `EssenceEffects.pointer_chance_of` — aggregated `1 − (1−p)²`, i.e. 50 % → 75 %, never `p × 2` and therefore never 100 %: a Pointer that always fires would stop being a chance; the Zündspule charm makes every fired link fire its target twice). A hit fires the target face **once**; if that face itself carries a pointer the chain continues hop by hop at the plain p, cycles allowed, bounded by `POINTER_HOP_CAP` (32 — a guard against pathological RNG, not a rule). A miss carries nothing over: the rolls are independent, and a failed roll shows **nothing** in the ceremony.
A fired link is one firing like any other with the face swapped in: link eyes (transformed) → the link's face material (`MaterialEffects.*_once_for`) → die-bound charms **including ×crits**, evaluating the link's value (`value_override`) while targeting stays by the shown up values — still at the die's position in trigger order, and never retriggered. Links never join hand detection and never fire **Runen** (a rune belongs to the up face). They now fire **interleaved**, right after their own die trigger.
**Rolled ONCE, then frozen.** `DiceScoring.roll_pointer_fires(die, up_face, die_triggers, face_triggers, charms, essences, rng)` takes an injected `RandomNumberGenerator` (seedable in tests) and is called exactly once per take, from `scene_root._roll_pointer_fires`, when category, order and echo slot are fixed. The result goes into `DiceScoring.CTX_POINTER_FIRES` (slot → array over die triggers → the fired links; empty inner array = the roll missed) and **scoring, `ScoreBreakdown` and `apply_take_effects` all consume that same frozen structure** — never roll twice. The **preview lacks the key** and therefore scores without Pointer; the farkle verdict is rank-only and unaffected. Running values travel inside the roll (`MaterialEffects.mutate_link_value_once`, the shared helper take effects use), so a bone link fired twice counts the grown value the second time and the def lands on exactly that number. Gold pays **per fired occurrence**, and the Gold-III pre-pass counts fired occurrences + essence links + the die×face up-face count.
**Deterministic links** are the counterpart to the rolled Pointer, and there are exactly **two** paths, split by their timing. **Röntgenlicht** (opposite face) comes from `EssenceEffects.essence_link_faces(die, up_face, essence_ids)` and fires **once per die trigger**, right behind that trigger's firing batch — like a guaranteed Pointer, but no chance, no chain and never a rune; it rides `CTX_ESSENCE_LINKS`, and `DiceScoring.essence_link_groups` is what rolls its value forward over the triggers (a bone link grows between them). The **Kehrseite rune** (opposite face) comes from `EssenceEffects.link_faces(die, up_face, rune_ids)` and keeps the old once-after-all-triggers path on `CTX_DET_LINKS`. Both are resolved once in `scene_root._link_map` (`_essence_links`/`_det_links`), remapped in `_score_ctx_for_slots`, snapshotted as `pre_reroll_essence_links`/`pre_reroll_det_links` for `is_strictly_better`'s `old_ctx`, and resolved by take effects straight from the defs. A Röntgen die that also carries a Kehrseite fires its opposite face per trigger **and** once at the end — deliberately no hidden dedupe. All three walks (`_base_and_mult`, `ScoreBreakdown.build`, `apply_take_effects` incl. the gold pre-pass) run the same nesting, and the Manometer repeats both link kinds like every other soul effect.
Applied in the Werkstatt: the EPIC dice-category engraving **"Pointer"** (one of the two Sonderposten, next to the Veredelung: `material_id()` returns `""` for every `is_special_id`, so neither lies on an Ikonensatz and the press can only ever hand one out as the fixed content of its own pack) uses the Meißel-style two-step pick with the second pick adjacent-only; overwrite allowed. `DieNetView` draws each pointer as an arrow on the source cell's border matching the crossed cube edge (`POINTER_SIDES` — adjacent faces aren't always adjacent net cells, so no connecting lines), and during counting the fired link pulses reuse `_play_die_pulse` while the pit net re-shows the die with the link face gold-framed.

**Veredelung (normal vs. veredelt).** The player-facing word is **Veredelung** — every UI text and every German comment says "veredelt"; the code keeps `dope`/`doped`/`levels`/`Engraving.DOPING`, the same UI-vs-code split as Energie/`charge` and Gravur/`Engraving`. (It was called "Dotierung" until the material theme won.) `DieDefinition.levels` holds, per face, the state of the material *sitting on that face* — **0 = none, 1 = normal, 2 = veredelt**, and there is no third rung: `DieMaterial.MAX_LEVEL` is 2, so every `level >= MAX_LEVEL` check reads "is this face doped". The state belongs to the material **instance**: `set_face_material` is the single write path for `materials[face]` precisely so that overpainting always resets it to undoped (Midashandschuh, the material engraving and both die factories all go through it) — but it never touches the face's **rune**: die Veredelung wohnt in der Glasur, Runen in der Struktur der Schale. **Die Veredelung is a Sonderposten, the Pointer's twin in every respect** (`Engraving.DOPING`, EPIC, `CATEGORY_MATERIAL`): bought in the Schwarzmarkt, bought in the **normal shop from hub level 8** (see *Sonderposten im Handel*), won at the Nebenwette Reinraum (`SideBet` `clean_room`, the one `Payout.SPECIAL` besides the Platinenauftrag), sealed as a Fixinhalt-Paket, pressed like everything else, then placed BY HAND on a clamp net. It is deliberately a **material** engraving that belongs to no material: `material_id()` returns `""` for every `is_special_id`, so it lies on no Ikonensatz and the press can never roll one — but its sealed pack is a Material-Paket and its Ablage chip glows in the Material sort colour, because saturating a glaze is what it does. Targeting is ONE click on a face that already carries an undoped material (`PressTargeting.eligible_faces`); a naked face has nothing to dope and a doped one nothing left to gain, so both dim. The Einbrand bars only *overpainting*, never the glaze on top. `GameRun.apply_press_doping` books it, and `die.dope(face)` IS the legality probe — a face that does not move is not a target, so the piece survives a misclick. The two born-or-copied sources stay: the **Gütesiegel** charm dopes a face on the dice it refines (`DiceOffer`/`Pack`), and the **Meißel** from Stufe `CHISEL_MATERIAL_STUFE` copies a doped source face onto its target (unreachable while the press mints everything flat, kept for a future ladder). `DieDefinition.dope` stays the single write path. Fresh paint out of the press always lands **undoped** — the saturation is its own piece, never a rung on the material engraving. The old duplicate climb is **gone** — the same material engraving again on the same face is **not a target at all** (the face dims like any other non-target) and fresh paint costs exactly one copy. Each material's doped state is hand-set — sometimes scaling, sometimes transformation: Bernstein +20 flat **plus the eye sum**, doped only 5 × eye sum; Gold +$3, doped +$7 plus +$1 per gold-**face** trigger of that take (counted in one pre-pass before the first booking); Knochen grows +2 flat, doped max(10, 20 %) **compounding per activation**; Rubin +4 Mult, doped a **crit ×2**; Glas +eyes **capped at 6**, doped a **crit ×(eyes/2)** instead of any additive share — and it eats itself −1 undoped, half when doped. Both crit materials wait for the doping, and no material crit ever drops below ×1. The two doped crits are the reason the whole thing is order-sensitive: a material crit fires inside the die phase, in the crit sub-step **before** the essence crit and any die-bound charm crit, in both the activation and the link block — so `MaterialEffects.mult_bonus` can no longer express a full result and survives as an additive preview helper only, with `DiceScoring._base_and_mult` authoritative. Charms that raise a base number keep their **surplus above it** (Bernsteinzimmer +30 in both states, Knochenleim +3 over the step, Goldschmied +$3/Goldader over the state's rate — Knochenmark doesn't touch the step, it adds a **trigger**: every bone firing happens twice, flat, and the doped percentage step recomputes per trigger, so two triggers on 40 give +10 then +11, never 2 × +10) — never a factor on the raised value, or the doping would multiply with its own support charms. The per-die facts the effects need (up-face state, eye sum) ride in `ctx` like the Pointer chains (`DiceScoring.CTX_MATERIAL_LEVELS`, slot-keyed — **remapped** in `_score_ctx_for_slots` and snapshotted as `pre_reroll_levels`, or preview and farkle comparison silently judge the wrong dice); take effects read the defs directly. `DieNetView.level_badges` marks a doped cell in its bottom-right corner — free, because pointer arrows sit at the edge midpoints — as geometry, not type: at the 30-die grid's ~17 px cell a glyph is mush, so the dark plate with its three bars carries alone. The undoped face stays unmarked, it is the normal case. The station composes its own cells, so it adds the badges itself.

**Essenzen (die Seele des Würfels).** `DieDefinition.essence_id` is **innate**: sealed into the shell at casting, with no application path anywhere — only die factories and offers write it (`DiceOffer.roll_essence`, shared by shop, packs and the slot-machine die prize). `Essence` (data) carries name, `short`, `description`, rarity, `glow`, `secret` (Schwarzmarkt-only) and `unique` (Legendäre) — no epithet: every display site prints name + effect; `EssenceEffects` (core) resolves the behaviour by id. **Kanten-Materialien are gone entirely** — the edges are no longer an upgrade slot, only the stage the essence glows on (`DieFaceDisplay` tints the frame by `Essence.glow_for`, essence-less dice keep the neutral neon). Consequences that must hold: **the essence is the only factor on the Würfel-Achse** (`activation_factor` — Argon 2, Quecksilberdampf 3, Elmsfeuer 2/4 im Stresstest, and the Quecksilberlampe **charm** adds +1 to any factor ≥ 2), and there are exactly **two axes** (see *Zwei Auslöse-Achsen* above), so `Faktor × Faktor` can never explode again. `secret` essences never appear in the normal shop or in packs, `unique` ones are excluded once owned and never roll onto a bundle > 1, and a purchase that *does* write straight into the pool (shop dice, slot-machine die) replaces a **soulless** slot first (`GameRun._replace_pool_entry`) because a soul is not re-obtainable — the Schwarzmarkt die goes the sealed-pack way instead and never overwrites anything by itself. The essences ride the ctx as `DiceScoring.CTX_ESSENCES` (slot → id), `CTX_ESSENCE_SET`, `CTX_RUNES`, `CTX_PHOSPHOR_STORE` (slot → stored base points; run-long state only `GameRun` knows — it accumulates and is never emptied) `CTX_PHOSPHOR_MULT` (the same store's mult half, only filled by the Leuchtstoffröhre) plus the hand-wide `CTX_STRESS`, `CTX_ROUND_TRIGGERS` and `CTX_ROUND_CRITS` (what the round's earlier hands brought — only Dunkelkammer and Gewitterfront read them); every slot-keyed one is remapped in `_score_ctx_for_slots` and snapshotted as `pre_reroll_*`. A **third shape of repetition** sits next to the two axes and must not be confused with them: `EssenceEffects.essence_repeat_count` (Manometer) repeats what the SOUL does, never what the die does — its crit (each repeat its own slam, Härteofen grammar), its money per firing, its face growth and its deterministic links. Lenses, Antimaterie's inversion, Krypton's always-scored, protections and every charm-/material-owned effect stay single. **No essence touches the trigger order** — `trigger_order` knows only the canonical combination-block rule (see *Die-phase order*) and the player's declared arrangement.

**Krypton widens the scored set** — and that is *all* it does. It joins `hand_shape`'s `scored` even when it is not part of the combination (`EssenceEffects.always_scored_of`, appended after the legal filter and re-sorted) — but never `participating`, so detection, the combo charms (Snake Eyes, Zwillingsring) and the Zauberkarte's extra die trigger never see it. That is the Vollzähler distinction, and the append must go onto a **copy**: without the Vollzähler, `scored_indices` hands back the very same array as `participating`. The append iterates the **legal** slots, which is what makes a parity-barred Krypton stay barred (see *Parität*). `scene_root._hand_slots` pulls a lying Krypton die into the hand even unselected, otherwise the scoring would never be handed the die it is supposed to always count.

Three shapes an essence effect can take, and each has exactly one seat: a **lens on the shown value** (Wasserstoff ×2) sits in `DiceScoring.shown_values`/`shown_value`, right after the charm transform chain — so detection, targeting and the pit preview all see the doubled number while `raw` (the physical faces, and with them the value mutation and `score_category`) stays untouched; **link faces** (Röntgenlicht's opposite, once per die trigger) come from `EssenceEffects.essence_link_faces`, which the scoring ctx, the take effects and the gold-trigger pre-pass all call — the Kehrseite rune keeps its own once-path in `link_faces`; and **permanent face growth** (Helium, Strahlungsdruck) rides `MaterialEffects.mutate_value_once` for the up face while the take writes the remaining five, so simulation and def can never drift. An essence that pays at the **round's end instead of inside a hand** is a fourth shape and stays a pure helper: Knallgas' chain reaction is `EssenceEffects.leftover_die_payouts(souls_in_deck_order, base, charms)`, which returns the payout **per leftover die** and which `scene_root._on_round_complete` uses in place of the old scalar `per_die` — the Wartungsvertrag still kills the whole row, and with it the chain. An effect that reaches into the **run's stock instead of the score** is a fifth shape and does NOT belong in `core/`: the effects class only carries the predicate, the effect itself is a `GameRun` method called from the take, next to `apply_carbon_copy`/`apply_glaze_brush`. The Abguss rune is the reference (`RuneEffects.casts_material` → `GameRun.apply_rune_cast`) — its once-per-round mark lives in `rune_cast_used`, keyed by `get_instance_id()` like every other per-round die mark and cleared in `roll_essence_round_state`.

**Krits are floats.** `EssenceEffects.crit_once_for`/`crit_of`, `MaterialEffects.mult_crit_once_for` and both `CharmEffects` crit hooks return `float`, and the mult side of `DiceScoring._base_and_mult` is a float all the way down. There is **exactly one rounding in the whole formula** — `ceili(base × mult)` at the merge — so two Xenon crits are ×2.25, never twice-rounded ×2. The crit *count* (Ozon's ramp, Grubengas's per-crit bonus) therefore compares with `is_equal_approx(crit, 1.0)`, never `!= 1`. Every printed mult goes through the one format rule `ScoreBreakdown.format_mult`/`format_number` ("×2", "×1.5", "×2.25"); the combo chips keep printing their integer level mult.

**Runen (Kernlicht).** A rune is a sign etched so deep into the shell that it taps the die's core-light spark — the tint IS the effect. `DieDefinition.runes` holds one per face; `second_runes`/`third_runes` are parallel arrays that **only Vakuum dice** may write (`rune_slots()`, the third only under the Glasglocke charm), and the Vakuum's runes render **black** whatever the type. Six kinds in three classes: **Nachglühen** (Wertung) adds +1 activation, additive like every non-essence source; **Funkenflug** (Wertung) mints +1 ⚡ once per Zug — the fourth charge source, booked in the take and flown afterwards; **Kehrseite** (Wertung) fires the opposite face once after all die triggers, deterministically — the same face the Röntgenlicht lights, only at the face instead of the soul and once instead of per trigger (see *Deterministic links*); **Streulicht** (Ökonomie) pays +$1 (Stichel: $2) for every die that lies **unscored** at the end of the Zug showing that face (the deliberate counter-event to Gold, hence `apply_take_effects` takes the `lying` slots); **Abguss** (Ökonomie) casts a copy of the scored face's material engraving into the workshop **as a sealed Fixinhalt-Paket** (`Pack.fixed_engraving`; its reader lands locked on that icon and plays in the hand) — the fifth effect shape (it reaches into the stock, not the score), so `RuneEffects` carries only the predicate `casts_material` and `GameRun.apply_rune_cast` books it next to `apply_glaze_brush`, **once per round and die** (`rune_cast_used`, keyed by `get_instance_id()`, cleared in `roll_essence_round_state` — without that limit an Argon die prints engravings on a conveyor belt), no material on the face = no cast, and the copy is always **undoped**; **Einbrand** (Schutz) burns the face value in — it cannot shrink (glass, Radon decay both skip it) and its material cannot be overpainted, while doping that same material, value engravings and re-etching stay allowed. Runes belong to the **up face**, so Pointer links and Kehrseite firings never fire them — that rule is what stops two opposing Kehrseiten from escalating into each other. They travel as `DiceScoring.CTX_RUNES` (slot → id list), remapped and snapshotted as `pre_reroll_runes` — the Nachglühen changes activation counts, so the farkle comparison needs the old runes. Acquisition is the **Runen-Paket** through the Presse: the six rune engravings (`Engraving.RUNE_PREFIX` + rune id) are its Ikonensatz, and a rune piece places its rune **once** — an occupied slot is replaced, never a strength upgrade. (Quantity comes from the press's Multicast now: one Kolossal pack can throw up to 25 rune pieces.)

**Where a rune sits is a separate decision from what it looks like.** The geometry has ONE source (`Rune.glyph_lines`, normalized polylines) feeding both the net view and the generated 3D overlay texture, and it is written in **cell coordinates (0..1), not face coordinates** — the drawing is never mixed with its placement. `Rune.ANCHOR_CELLS` holds one cell per rune slot in face coordinates (lower-left / upper-right / lower-right shoulder), each chosen as large as `DIGIT_KEEPOUT` allows and **wholly outside** it. That split is forced: a crack ran edge to edge and therefore kept clear of the digit by itself, a compact sign does not — so the **cell** keeps the digit free now, and `test_rune_geometry` guards both halves separately (cell clears the keepout, figure stays inside its cell with `GLYPH_MARGIN`, and the placed figure clears the digit on every slot). The margin is not decorative: it equals `RuneTextures.FIELD`, so the flare — which only widens the *baked* field — ends exactly at the cell edge instead of being sliced into a rectangle. A second rune on one face therefore takes the **opposite shoulder** rather than being mirrored: the shader's old `mirror` bool is gone, replaced by a `cell` uniform, which is also what lets one texture serve all three slots. The **Würfelnetz uses the same shoulders but bigger boxes** (`Rune.NET_CELLS`, quadrants, via `cell_to_net`): it draws no lit 3D digit and has no bloom, so nothing there needs the keepout — its constraint is size, and at a 17-40 px tile the die's tight anchor cell would be a 5 px scribble. Same figure, same corner, different box; the geometry source stays single. `RuneTextures` bakes one colourless mask per glyph (~39 ms each at `SIZE` 192, 234 ms for all six — cheaper per mask than the old cracks, dearer in total), and the stroke has **constant depth** with only a short run-out at free ends; the crack taper is gone. Timing separates the two light systems: the essence glows **constantly**, a rune only shimmers at rest and **flares in the moment it fires** (`DieFaceDisplay.flare_runes`, driven from `_flash_scoring_die`). `IDLE_CEILING` still forbids idle bloom, and there are no per-rune lights — the tiled ground's 16-light budget forbids it, so emission carries alone.

`ScoreBreakdown.build` mirrors the formula 1:1: every die step carries one group per Würfel-Trigger (`die_triggers`, each `{firings, links}` — a firing is die pulse → `charm_*_add/after` → the `crit_steps`) plus the trailing `det_links`, played by `scene_root._play_die_step`. **The combination travels pure**: `combo` carries the plain `points_for`/`mult_for`, and each Dreifacher-Boden copy is its own `combo_factor_step` right behind it (dock indices so the pad flashes, plus `base_after`/`mult_after`; only `base_after` moves, the combination's mult stays pure) — same rule as the crits, one step per copy instead of one `×3^n`. Folding the factor into `combo` silently made the counter show a number whose origin was nowhere on the table. The sums are unchanged by construction and a test nails them against `DiceScoring.score_category`; the charm has no `charm_*_at` hook, so it can never appear in `charm_steps` as well. **Every crit is its own slam**: `crit_steps` lists material, essence and then EACH die-bound charm position separately (`_crit_step`), so a doped Rubin under the Härteofen hits twice ×2 instead of once ×4 — `crit_x` survives only as their product for the tests; static charm steps stay in the charm phase (`_play_crit_step` for static crits, Beherit among them). When adding a charm, put it in the class where it belongs — a die-bound effect in the `die_charm_*` hooks, a static one in the `charm_*` hooks — or the animation fires it in the wrong phase.

The same rule holds at **round end**: after the round payout and before the shop opens, round-end charms fire strictly left to right in `scene_root._play_round_end_charm_ceremony`, and every effect is **visible** — money charms (Zinsgroschen, Überflieger — $5 per **cleared overcharge stage**, i.e. the visible bar, so the Doppellader's second ⚡ per stage changes nothing —, Glücksgroschen, Notgroschen) pay as **real chip denominations** (`ChipStackView.split_gain`, each packet in its chip color) launched in a dense stagger from the dock pad, every packet booking its own value on arrival; the Dynamo books its ⚡ and lets the light fly afterwards; Frankiermaschine mints `GameRun.STAMP_PACKS` (1) sealed Pakete per copy and flies them down the workshop ader (`STAMP_METEOR_GAP` between launches, no waiting for the previous arrival), each granting on its own arrival (`GameRun.roll_stamp_pack` rolls the sort, the ceremony grants); the **Füllhorn** pays off the same bar the Überflieger reads — from `GameRun.ENCORE_STAGES` (5) cleared overcharge stages on, `apply_encore(stages)` books one sealed Sonderposten per copy at `_on_round_complete` and `_play_encore_meteor` flies it to its Magazin spot, where its withheld cassette rises out of the pit floor (`_fly_pack_to_magazine`, the one Magazin arrival; the round end IS the once-per-round rule, no flag); the **Schmuckkästchen** grants **Fixinhalt-Material-Pakete, never a face** — it was booked back at `_on_round_complete` (`apply_jewelry_box` returns one `{material_id, copy, pack}` per find; `copy` names the dock seat it belongs to, so several charm copies do not all fire at the first pad) and shows it here as the same dense volley, each meteor ending on its own Magazin spot. All of it travels the LED-strip route through score window, pit and hub (see *Light routing*). A new round-end charm gets its case in that ceremony — never a silent mutation in `GameRun`.

## Testing notes (GUT quirks)

- **`test/unit/`** — fast pure-logic tests (no scene tree). **`test/integration/`** — tests that build nodes.
- GDScript won't auto-convert untyped array literals to the typed `Array[int]`/`Array[String]` these APIs expect — use the `_d()`/`_ids()` helpers (they `.assign()` into typed arrays). Pulling from an untyped `Dictionary` needs an explicit type (`var k: String = h["key"]`, not `:=`).
- `assert_signal_emitted_with_parameters` chokes on **bool** params (crashes in `signal_watcher.gd`/`diff_tool.gd`) — record emitted values manually via a `connect` lambda and assert the resulting array instead.
- `get_global_rect()` on freshly-built container children returns a zero rect until a frame passes — `await wait_frames(2)` before asserting layout.
- For inspector/engraving tests that apply etchings: `view.run = GameRun.new_run()` then `view.run.grant_engraving(Engraving.chisel())`.
