# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Fumble** — a Balatro-like 3D dice roguelike built in **Godot 4.7** (`gl_compatibility` renderer, Jolt physics). Code comments and in-game text are in **German**; identifiers are a mix. The whole game plays on a single table surface at world **Y = 0**, viewed as a "casino table screen": 2D UI is rendered into a `SubViewport` and displayed on a mesh (see Architecture). The table has **no edge**: the felt runs on as an endless floor that fades into the dark room (`TableGround`), leaving space for future features around the play area.

**Comments:** keep them to the necessary minimum — short German one-liners that state a non-obvious rule, constraint, or design decision. Don't restate what the code already says, don't duplicate a `description` string that sits one line below, and don't write essay-length narrative blocks or "siehe X" cross-reference chains. When in doubt, cut it.

## Architecture

### Layered `scripts/` — the folder IS the dependency rule
`core/` and `data/` must not import from folders below them. New scripts are placed by layer, not by feature:

- **`data/`** — reine `Resource`-Records (inkl. `DealClause`); jede Id als `const`-String (single source of truth). Details: `scripts/data/CLAUDE.md`.
- **`core/`** — pure Logik, **keine Nodes** (`RefCounted`/static): Scoring, Effekt-Auflösung, `GameRun`, Verträge, Energie-Ökonomie. Details: `scripts/core/CLAUDE.md`.
- **`dice/`** — der physische Würfel: Physik, Builder, Face-Display, Schwebe-Stationen. Details: `scripts/dice/CLAUDE.md`.
- **`table/`** — 3D-Requisiten, Kamera und das Tisch-Display samt Bühnenmaschinerie (Vitrine, Hebebühne, Data-Cells, Licht-Routing). Details: `scripts/table/CLAUDE.md`.
- **`ui/`** — 2D-Fenster und Styling im Tisch-Display: Laden, Werkstatt/Presse, Magazin, Wetten. Details: `scripts/ui/CLAUDE.md`.

Die ausführliche Architektur-Doku liegt in diesen verzeichnis-lokalen CLAUDE.md-Dateien; Claude Code lädt sie, sobald dort Dateien angefasst werden. Wer ein Subsystem anfasst, liest die CLAUDE.md seines Ordners zuerst — Querverweise („siehe *X*") können in einer Schwesterdatei liegen.

### `scene_root.gd` — the single coordinator
Top-level `Node3D` (not in a subfolder). Owns exactly one `GameRun`, wires its signals to the UI, drives round flow (throw → score → take/reroll → round-goal → **Auszahlungs-Seite mit Kassieren-Halt** (der Hub wird zur Cash-Out-Seite und die Runde steht, bis „Kassieren" gedrückt ist — siehe *Die AUSZAHLUNGS-SEITE* in `scripts/ui/CLAUDE.md`) → shop — and the **pit is the shop's second exit**: focusing it while `phase == SHOP` means "Fertig", so `_on_camera_mode_changed` calls `ShopController.close()` and `_on_shop_closed` only zooms back to the overview when the camera really stands in the hub, never yanking back a flight already under way), and passes the same `GameRun` instance (typed) to `ShopController` and `WorkshopView`, which mutate state **only** through `GameRun` methods. It also does mouse-forwarding: `_forward_screen_mouse` projects window clicks onto the table plane and `push_input`s them into the `SubViewport` (the projection is camera-independent and runs in every pose, the free camera included); `_screen_forwards_pixel` asks which VISIBLE window owns the pixel — see *Sichtbar heißt bedienbar*. `_ready` is split into named setup steps (`_setup_dice`/`_setup_table_screen`/`_setup_camera_targets`/`_setup_panels`/`_setup_settings_ui`); camera raycasts go through the shared `_ray_pick(pos, mask)` helper and click zones through `_add_click_zone`.

### Globale Invarianten (Kurzform — Volltext in den Ordner-Dateien)
- **Buchung vor dem Licht**: `GameRun` bucht, die Zeremonie zeigt nur an — neue Quellen buchen VOR dem Flug; die wenigen benannten Zeremonien, die bewusst am Einschlag buchen (Bank-Discharge, Frankiermaschine, Geld-Pakete), sind phase-/run-guarded. Nie doppelt.
- **Endzustand zuerst** (`seat_hard`-Regel): jede Fahrt schreibt erst den fertigen Zustand und fährt dann den Weg dorthin; ein abgebrochener Tween darf nichts schulden.
- **EIN idempotenter Schreiber je Körper-Ort**, mit Generations- und Lauf-Marken; jeder Abbruch läuft durch EINEN Aufräum-Pfad.
- **ui/ fasst nie Körper an**: Fenster malen Fassungen und MELDEN Rects/Anker in Display-Pixeln (das `apron_bottom`-Muster); die Körper gehören `scene_root`.
- **Ein Würfel wird nie zweimal gezeigt.**
- **Der VORRAT hat ZWEI ANSICHTEN, und der RASTER-UMSCHALTER legt um** (2026-09-03): KÖRPER (die schwebenden Würfel) oder RASTER (die GLAS-ANSICHT — der Vorrat versinkt, der Gruben-Schirm fährt zu und trägt die Anzeige, und darauf liegt das Netz-Raster des Vorrats, Sitz i = Zelle i). Der Umschalter ist eine flache Taste auf dem freien Filz ÜBER der Grube (`RasterSwitchView`, bündig mit deren Bildschirm-rechtem Ende — die eine Kante, an der neben dem Loch noch Platz ist, und sie steht an Pool- wie Werkstatt-Station im Bild); ihre Aufschrift nennt, was der Druck LIEFERT („RASTER" / „KÖRPER"), und blind bleibt sie STEHEN und wird nur grau. **Der ZELL-TIPP bedeutet zweierlei, und der Neuzugang entscheidet**: wartet einer im Ausgabefach, ist die Zelle sein Tausch-Ziel (`exchange_pending_die`, gebucht sofort), wartet keiner, wählt sie wie der Tipp auf den Pool-Körper das ZIEL der Serie (`WorkshopView.set_target_die`; die Bühnen-Fahrt aufs Podest wartet auf den stehenden Vorrat, holt ihn also beim Schließen) — und die gewählte Zelle trägt den Gold-Saum. Zug legt um, Rechtsklick schließt, das ZURREN schließt HART (das Raster darf nur stehen, solange der Vorrat stehen dürfte). **ZWEI Wege hinein, EIN Weg hinaus** (`_close_deck_glass`, hart `_settle_deck_glass_hard`): der UMSCHALTER öffnet den DAUER-Modus (`_deck_glass_pinned`) — er rahmt NICHT um, merkt sich keine Station und überlebt darum den Stationswechsel; der TIPP auf einen Neuzugang öffnet die enge Tausch-Frage, die ENG heranfährt (Rahmen = Pool-Loch ∪ Neuzugangs-Säule, ~85 % Bildfüllung, TEMPORÄRER Rahmen ohne Moduswechsel), an die gemerkte Station zurückkehrt und beim Wegzoomen abbricht. **Liegen mehrere Neuzugänge, bleibt sie nach einer Wahl STEHEN** (die SERIE, 2026-09-01): der nächste rückt ins Fach nach, Kopfzeile und Info-Säule wechseln auf ihn — und weil `exchange_pending_die` die Indizes verrutschen läßt, ist der offene Neuzugang IMMER Index 0. Das Raster prüft seine Frische am INHALT (`DeckGlassView.pool_signature`), nicht an den Referenzen: der Tausch schreibt per `become` in die Instanz, die Liste bleibt gleich. Die Pool-Maschine kennt für das Raster eine ZWEITE Park-Konfiguration (tief, mit Schirm); die der RUNDE (flach, schirmlos) bleibt unberührt. Das Raster wohnt seit 2026-08-31 in einem EIGENEN, nicht-HDR-SubViewport mit `transparent_bg`: nur so trägt es echtes Per-Pixel-Alpha (der Helligkeits-Key und die Filz-Schwärzung sind damit gestorben), und seine Auflösung wird an der GEMESSENEN Bildschirm-Pixeldichte des Schirms bemessen statt am fernen Ausschnitt der einen Anzeige — gemessen 1,35 Texel/Pixel an der Pool-Station und 1,64 an der Werkstatt-Weitsicht (dort ist das Raster nur KLEINER: Netz-Zelle ~7,8 Bildschirm-px gegen ~11,7 am Pool, gemessen bei 1280 × 720). Siehe *Die GLAS-ANSICHT* in `scripts/ui/CLAUDE.md`.
- **Es gibt ZWEI PODESTE: der FACH-SITZ und das ERGEBNIS-PODEST** (2026-09-03, Korrektur-Welle G — `podium_stage`, `_inspected_die`, `_toggle_pool_podium`/`_open_pool_podium`/`_settle_podium_hard`/`_rebuild_podium_stage` bleiben fort). Das LINKE Podest IST der Sitz des AUSGABEFACHS, exakt (`scene_root._fach_podium_target()` aus `AusgabefachView.open_spot()`/`floor_top_y()` plus `PODIUM_HOVER` = `DiceTrayView.FLOAT_HEIGHT`): der TIPP auf einen VORRATS-Würfel wählt ihn als ZIEL der Serie (`WorkshopView.set_target_die` — derselbe wählt ab, ein anderer wechselt), und er fährt per **Bühnen-Fahrt** aus dem Pool genau dorthin, wo die Neuzugänge liegen; sein Pool-Sitz bleibt derweil LEER (`_bench_die` → `DiceTrayView.seat_shows`, die eine Sichtbarkeitsregel), und seine AUSKUNFT trägt die INFO-SÄULE darunter (`FachNetView`). Das gilt an JEDER Station: `_wanted_bench_die()` fragt nur noch das Fenster, nicht mehr die Kamera — die Fahrt selbst wartet ohnehin auf den stehenden Vorrat. Rechtsklick wählt ab; ein Kamerawechsel NICHT (das Podest gehört dem Fenster, nicht der Station). **`AusgabefachView.set_curtain` ist darum ZURÜCK**: solange ein Ziel gewählt ist oder die Bühnen-Fahrt läuft (`_bench_die != null or _bench_riding`), sinkt der wartende Neuzugang unter den Fachboden — der Platz gehört dann dem Zielwürfel —, und steigt wieder auf, sobald er frei ist (`scene_root._sync_fach_curtain`, je Bild gefragt). Das RECHTE (Ergebnis-)Podest steht im Werkstatt-Streifen und trägt den Würfel NACH der Serie: die **ÜBERGABE** wechselt ihn am Ende der Schablonen-Fahrt per HEBEBÜHNE die Seite — links versinkt der Körper, rechts steigt ein frisch gestellter (dieselbe Zwei-Bein-Grammatik wie Pool ↔ Bühne, EIN Körper), die Schablone faltet sich DORT in ihn, und der Soll-Schirm zeigt danach das ERGEBNIS mit grünen Deltas, bis ein anderes Ziel gewählt oder abgewählt wird. WO er steht, sagt `_bench_side` neben `_bench_die`; beide schreibt allein `_seat_bench_place`, die Schwebehöhe je Seite `_bench_hover_for`, und `result_stage` ist nur noch der leere Puck, der dem Körper weicht. Der Vorhang bleibt dabei unten (`_sync_fach_curtain` fragt die Seite nicht), greifbar ist er auf beiden Seiten gleich, und der Rückweg in den Pool startet an der Seite, auf der er steht. Der EINE harte Abschluß der Übergabe ist `_settle_bench_handover_hard` (Skip mitten in der Fahrt), der EINE harte Aufräum-Pfad bleibt `_migrate_bench_to_pool`.
- **Der DOPPELKLICK auf den Podest-Würfel öffnet die INSPEKTION** (2026-09-01, an der Straße seit 2026-09-03 die einzige Nah-Geste): die Kamera fährt SUPER NAH heran — Rahmen = halbe Raumdiagonale mal `CameraRig.DIE_FOCUS_MARGIN`, gemessen ~7× näher als die Station —, der Würfel legt sich in die Dreiviertel-Ansicht (`die_focus_basis`, drei Seiten auf einmal), die Kamera steht STILL, und ein ZUG dreht IHN um die Bild-Achsen (`FloatingDie.spin`; ohne Fokus dreht derselbe Zug ihn an Ort). Es gibt **keinen Seiten-Pick** — hier wird gedreht und geschaut, nicht graviert. Sie ist **MODAL wie die Glas-Ansicht**: im Bild steht nur der Würfel, `_screen_forwards_pixel` schweigt, und WASD wie Doppelklick-Nahsicht sind taub. Wie die Glas-Ansicht ist es ein **TEMPORÄRER Rahmen**: `zoom_die_focus` meldet keinen Wechsel und rührt den Modus nicht an; die Lage davor merkt sich `scene_root._die_focus_home`. Rechtsklick und Rad-zurück gehen **EINE Stufe** aufs Podest zurück (`_leave_die_focus`), erst der nächste wählt ab — Fokus → Podest → Abwahl.
- **Das Bewegungs-Gesetz liest sich nach URHEBER**: was der *Spieler zahlt*, fliegt als KÖRPER im ballistischen Bogen (der WURF, `scene_root`s `#region Der WURF`); was der *Tisch liefert*, reist als LICHT über die gelegten Adern (die AUSNAHME seit der Korrektur-Welle I: Kassetten-Lieferungen ANS MAGAZIN fliegen als reiner METEOR-BOGEN ohne Ader, denn die Hub→Magazin-Ader ist gefallen; die Quell-Adern von Automat und Schwarzmarkt leben weiter); was er *präsentiert oder einzieht*, fährt per HEBEBÜHNE durch die Fläche. Umgesetzt ist der Wurf bisher für den Nebenwetten-EINSATZ — Laden und Werkstatt zahlen noch Licht, ihr Umzug ist eine spätere Welle. Die ABLAGE eines benutzten Würfels ist dagegen ein EINZUG des Tisches und fährt darum per HEBEBÜHNE: eine würfelgroße Sektion öffnet unter seinem Liegeplatz in der Wurfgrube und senkt ihn ein (der SCHLUCK, `scene_root._swallow_dice`; der ballistische Ablage-Flug der Kuhle ist 2026-08-30 gestorben, siehe *Die WÜRFEL-BÜHNE* in `scripts/table/CLAUDE.md`). **Die eine benannte AUSNAHME ist die Wett-STEUER** (`scene_root._fly_bet_tax`): die Kleinsteuer je Hand ist kein Zahl-Moment, sondern ein Ticken, und sie reist darum als Meteor vom Schatz zum Wettfenster, wo der Bedingungs-Text kurz aufleuchtet. Neue Ausnahmen werden hier benannt oder es gibt sie nicht.
- **Die WERKSTATT ist eine SERIENSCHALTUNG** (2026-09-01): jede Gravur-Kassette trägt ein bei der Erzeugung gewürfeltes, überall SICHTBARES Prägenetz (`Pack.stamp_net`); bis zu `series_slots()` Karten stecken in Reihenfolge, `SeriesResolver` summiert sie seitenweise (Operatoren wirken auf die aufgelaufene Summe — die REIHENFOLGE ist die Entscheidung), und EIN Griff je Sitzung projiziert alles auf EINEN spielergewählten Würfel, der per Bühnen-Fahrt aus dem Pool kommt. Presse-RNG, Multicast, Ablage, Platzier-Zweiklick und das Aufspannungs-Los sind tot; der Zufall wohnt im Laden-Angebot. Siehe *Die SERIENSCHALTUNG* in `scripts/ui/CLAUDE.md`.
- **Die WERKSTATT ist eine STATIONS-ZEILE, rechts vom Pool, auf Pool-Höhe** (2026-09-03; Korrektur-Welle G nahm ihr den Fenster-Hintergrund und die beiden kleinen Schirme): der Streifen hat **keinen Schirm** mehr (`StyleBoxEmpty`, keine `window_*`-Uniforms im Glas) — seine Teile liegen auf dem Filz und lesen von LINKS nach RECHTS: die SCHACHT-REIHE (je Serien-Slot ein Loch im erhabenen Konsolen-Blech, in dem die ECHTE Data-Cell aus dem Magazin aufsteigt und geneigt stehen bleibt, Netz-Fläche zur Kamera) und die ERGEBNIS-SPALTE (Ergebnis-Podest über dem SOLL-SCHIRM). **Seit der KORREKTUR-WELLE I (2026-09-03) ist der SOLL-SCHIRM das UI-SPIEGELBILD des linken Netzes**: physischer Würfel + NETZ direkt darunter, GLEICH GROSS wie die Info-Säule links (`result_net_cell` aus `FachNetView.net_cell()`), auf BLANKEM FILZ — sein eigener Hintergrund ist gefallen —, und das Netz zeigt den Würfel NACH dem Griff mit grünen Deltas; die Aufschlüsselungs-Zeilen und die Augensumme sind TOT (nur der Karten-Hover ⇄ Netz-Zellen bleibt). **Mit der KORREKTUR-WELLE J (2026-09-03) liest die Station in ZWEI ZEILEN plus Grube**: Zeile 1 Fach-Würfel | SCHACHT-REIHE | Ergebnis-Podest, Zeile 2 — EIN durchgehendes BAND — IST-NETZ | TOOLTIP-SCHIRM | SOLL-NETZ. Der Tooltip (der Info-Text-Schirm der Welle I, Inhalt und Schreiber unverändert) steht DIREKT UNTER der Schacht-Reihe und ist GENAU so breit wie sie; das Soll-Netz steht rechts daneben auf DERSELBEN Zeile und **IMMER da** — ohne Ziel und ohne Karte als leeres Kreuz, nie versteckt. Das Konsolen-Band darunter trägt nur noch den GRIFF-Knopf (mittig unter der Reihe, Slot-Zähler in der Aufschrift: „Griff 2/4" = gesteckt/Serienlänge, während der Fahrt „Fertig"); der Serien-Schirm bleibt gestorben. Darunter das MAGAZIN: rechts bündig mit der Fensterkante, unten mit der Pool-Unterkante (Korrektur-Welle H) und **links wieder bis auf die linke Kante des IST-NETZES** (Welle J, `shelf_left` von `scene_root` aus `_fach_net_span()` gemeldet). **`bench_rect()` streckt sich MIT — nach unten UND nach links**: genau diese Links-Verbreiterung war in der Welle H der Bug „Upgrades lassen sich nicht wählen", weil die EINE Weiterleitungs-Region nur die Höhe streckte; ein Test schickt darum einen Chip-Tap im linken Grubenteil durch den ECHTEN Forward-Pfad. Die alte Werkbank-Fläche UNTER dem Pool ist FREIER Filz. Das Fenster malt nur Münder und das Ergebnis-Podest und MELDET ihre Anker (`press_slot_anchors`/`press_display_anchors`, `result_net_center`/`result_projector_y`), die Körper gehören `scene_root`. `scene_root._fit_workshop_rect` legt den Streifen an: linke Kante rechts der INFO-SÄULE des Ausgabefachs (`_fach_net_span`), Oberkante bündig mit der Pool-Reihe; Fenster PLUS Schürze (Naht + Band + Naht + Magazin) füllen zusammen die Pool-Höhe, so daß die Magazin-Unterkante die Pool-Unterkante trifft — das Fenster ist darum etwas kürzer als die Pool-Reihe (`scene_root` schiebt die gemessene Pool-Höhe als `apron_bottom` herein). Die Kamera (`configure_workshop_target`) rahmt Schale, Info-Säule, Streifen und Magazin, OHNE den Pool — der Pool-Tipp wählt weiter von seiner eigenen Station. Siehe *Die STATIONS-ZEILE* in `scripts/ui/CLAUDE.md`.
- **UI-Wort vs. Code-Wort**: Energie/`charge`, Gravur/`Engraving`, Veredelung/`dope`, Pointer (die LED-Adern behalten „Leiterbahn"), Benchmark (nie „Blind"/„Ante").
- **Sichtbar heißt bedienbar**: was bedient werden darf, hängt an Sichtbarkeit, nie an der Kamera-Station. Es gibt genau ZWEI benannte Ausnahmen: der Setzen-Klick des Wett-Tresens (2026-08-26) — gewettet wird nur an der eigenen Station, aus der Ferne wird der Klick zum Zoom — und der Schwarzmarkt-KAUF (2026-08-30): gekauft wird nur an der eigenen Station, aus der Ferne wird der Klick zum Zoom; Hover, Schilder und Tooltip antworten überall, wo die Ware steht. Neue Ausnahmen werden hier benannt oder es gibt sie nicht.

## Arbeitsweise (Spieler-Entscheidung 2026-08-25)
- **Delegiert wird nur bei echten FEATURE-WELLEN** (neue Mechanik, mehrere Subsysteme, Umbau einer Grammatik) — dann Plan-Datei + Opus-5-Subagent wie gehabt. **Kleine Änderungen macht die Session SELBST**: Ein-/Zwei-Datei-Fixes, Konstanten, Farben/Maße, visuelle Tweaks, Bugs mit bekannter Wurzel. Kein Plan-Dokument, kein Agenten-Aufsatz für so etwas.
- **Getestet wird EINMAL AM ENDE**, nicht nach jedem Schritt: ein Suiten-Pass, wenn die Änderung steht (plus Boot, falls `scene_root.gd` angefasst wurde). Kein Wiederholen der Läufe, die ein Subagent gerade grün gefahren hat — sein Log prüfen genügt (immer mit dem `Ignoring|Parse Error`-Grep, siehe unten); der eigene Vollpass gehört vor den Commit.
- **Beweis-Aufwand nach Anlass**: Kennfarben-Aufnahmen, Pixel-A/B und Frame-Serien gehören zur Artefakt-Jagd (dort haben sie dreimal die echte Ursache statt einer Vermutung geliefert) — nicht zu Geschmacks-Änderungen.
