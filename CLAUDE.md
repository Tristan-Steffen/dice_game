# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Fumble** — a Balatro-like 3D dice roguelike built in **Godot 4.7** (`gl_compatibility` renderer, Jolt physics). Code comments and in-game text are in **German**; identifiers are a mix. The whole game plays on a single table surface at world **Y = 0**, viewed as a "casino table screen": 2D UI is rendered into a `SubViewport` and displayed on a mesh (see Architecture). The table has **no edge**: the felt runs on as an endless floor that fades into the dark room (`TableGround`), leaving space for future features around the play area.

**Comments:** keep them to the necessary minimum — short German one-liners that state a non-obvious rule, constraint, or design decision. Don't restate what the code already says, don't duplicate a `description` string that sits one line below, and don't write essay-length narrative blocks or "siehe X" cross-reference chains. When in doubt, cut it.

Locally never split the suite into two concurrent Godot processes: one instance already saturates the machine (measured: parallel 135 s vs. serial 65 s). ## Architecture

### Layered `scripts/` — the folder IS the dependency rule
`core/` and `data/` must not import from folders below them. New scripts are placed by layer, not by feature:

- **`data/`** — reine `Resource`-Records (inkl. `DealClause`); jede Id als `const`-String (single source of truth). Details: `scripts/data/CLAUDE.md`.
- **`core/`** — pure Logik, **keine Nodes** (`RefCounted`/static): Scoring, Effekt-Auflösung, `GameRun`, Verträge, Energie-Ökonomie. Details: `scripts/core/CLAUDE.md`.
- **`dice/`** — der physische Würfel: Physik, Builder, Face-Display, Schwebe-Stationen. Details: `scripts/dice/CLAUDE.md`.
- **`table/`** — 3D-Requisiten, Kamera und das Tisch-Display samt Bühnenmaschinerie (Vitrine, Hebebühne, Data-Cells, Licht-Routing). Details: `scripts/table/CLAUDE.md`.
- **`ui/`** — 2D-Fenster und Styling im Tisch-Display: Laden, Werkstatt/Presse, Magazin, Wetten. Details: `scripts/ui/CLAUDE.md`.

Die ausführliche Architektur-Doku liegt in diesen verzeichnis-lokalen CLAUDE.md-Dateien; Claude Code lädt sie, sobald dort Dateien angefasst werden. Wer ein Subsystem anfasst, liest die CLAUDE.md seines Ordners zuerst — Querverweise („siehe *X*") können in einer Schwesterdatei liegen.

### `scene_root.gd` — the single coordinator
Top-level `Node3D` (not in a subfolder). Owns exactly one `GameRun`, wires its signals to the UI, drives round flow (throw → score → take/reroll → round-goal → **Auszahlungs-Seite mit Kassieren-Halt** (der Hub wird zur Cash-Out-Seite und die Runde steht, bis „Kassieren" gedrückt ist — siehe *Die AUSZAHLUNGS-SEITE* in `scripts/ui/CLAUDE.md`) → shop — and the **pit is the shop's second exit**: focusing it while `phase == SHOP` means "Fertig", so `_on_camera_mode_changed` calls `ShopController.close()` and `_on_shop_closed` only zooms back to the overview when the camera really stands in the hub, never yanking back a flight already under way), and passes the same `GameRun` instance (typed) to `ShopController` and `WorkshopView`, which mutate state **only** through `GameRun` methods. It also does mouse-forwarding: `_forward_screen_mouse` projects window clicks onto the table plane and `push_input`s them into the `SubViewport` (the projection is camera-independent and runs in every pose, the free camera included); `_screen_forwards_pixel` asks which VISIBLE window owns the pixel — see *Sichtbar heißt bedienbar*. `_ready` is split into named setup steps (`_setup_dice`/`_setup_table_screen`/`_setup_camera_targets`/`_setup_panels`/`_setup_settings_ui`); camera raycasts go through the shared `_ray_pick(pos, mask)` helper and click zones through `_add_click_zone`.

### Globale Invarianten (Kurzform — Volltext in den Ordner-Dateien)
- **EINE Größe je Ding, überall** (Spieler-Entscheid 2026-09-04, Welle L): die Größe eines Objekts ändert sich NIE zwischen den Orten des Spiels, und ein kontext-eigener Maßstab ist ein Fehler, kein Feature. Eine Data-Card steht in `PackDrawerView.CASSETTE_SCALE` (2,184) — im Magazin, in der Schacht-Reihe, in der Laden-Vitrine, im Schwarzmarkt, als Wett-Gewinn, als geworfener Einsatz und auf der Auszahlungs-Ablage —, ein Würfel in `DiceTrayView.DIE_SCALE` (0,6). **Der ROLL folgt der LAGE** (Welle O, 2026-09-04): sie LIEGT quer in jeder Verkaufs-Auslage, in der Wette und im Wurf (um die Blickachse gerollt, Langseite waagerecht), und sie STEHT kappe-oben im MAGAZIN und im Serien-KERF. **STEHEND ist sie seit der Welle P HOCHKANT** (`DataCellView.STAND_YAW`, eine Vierteldrehung um die Hochachse, die wie der Roll der LAGE folgt): ihre Fläche zeigt nach Bild-LINKS, von oben ist sie ein SCHMALER, TIEFER Balken (gemessen 35,9 × 88,5 px statt 88,5 × 35,9), und Magazin wie Schacht-Reihe stehen damit Fläche an Fläche wie eine KARTEI. Kappen-Zeichen und ×n werden um denselben Yaw GEGEN-gedreht und lesen von oben aufrecht (`_apply_cap_yaw`). LIEGEND ändert sich nichts. Die EINE, hochkante Netz-Backung bleibt und füllt sie ohne Rand — auf der stehenden Karte liest sie darum um eine Vierteldrehung gekippt, und dafür gibt es das SUMMEN-NETZ im Streifen. `DataCellView.STAND_HEIGHT` (= `HEIGHT`) ist ihr aufrechtes Maß, an dem JEDE senkrechte Rechnung mißt — Einsinken, Aufstieg, Griff-Hub und die Tiefe jeder Grube; das ortsabhängige `stand_measure` ist tot. Wer eine Fassung baut, paßt SIE der Größe an — die Schacht-Reihe rechnet ihre Münder aus Kartengröße plus Fuge und läßt notfalls den ganzen Werkstatt-Streifen nach rechts wachsen, nie umgekehrt.

- **Der VORRAT hat ZWEI ANSICHTEN, und der RASTER-UMSCHALTER legt um** (2026-09-03): KÖRPER (die schwebenden Würfel) oder RASTER (die GLAS-ANSICHT — der Vorrat versinkt, der Gruben-Schirm fährt zu und trägt die Anzeige, und darauf liegt das Netz-Raster des Vorrats, Sitz i = Zelle i). Der Umschalter ist eine flache Taste auf dem freien Filz ÜBER der Grube (`RasterSwitchView`, bündig mit deren Bildschirm-rechtem Ende — die eine Kante, an der neben dem Loch noch Platz ist, und sie steht an Pool- wie Werkstatt-Station im Bild); ihre Aufschrift nennt, was der Druck LIEFERT („RASTER" / „KÖRPER"), und blind bleibt sie STEHEN und wird nur grau. **Der ZELL-TIPP bedeutet zweierlei, und der Neuzugang entscheidet**: wartet einer im Ausgabefach, ist die Zelle sein Tausch-Ziel (`exchange_pending_die`, gebucht sofort), wartet keiner, wählt sie wie der Tipp auf den Pool-Körper das ZIEL der Serie (`WorkshopView.set_target_die`; die Bühnen-Fahrt aufs Podest wartet auf den stehenden Vorrat, holt ihn also beim Schließen) — und die gewählte Zelle trägt den Gold-Saum. Zug legt um, Rechtsklick schließt, das ZURREN schließt HART (das Raster darf nur stehen, solange der Vorrat stehen dürfte). **ZWEI Wege hinein, EIN Weg hinaus** (`_close_deck_glass`, hart `_settle_deck_glass_hard`): der UMSCHALTER öffnet den DAUER-Modus (`_deck_glass_pinned`) — er rahmt NICHT um, merkt sich keine Station und überlebt darum den Stationswechsel; der TIPP auf einen Neuzugang öffnet die enge Tausch-Frage, die ENG heranfährt (Rahmen = Pool-Loch ∪ Neuzugangs-Säule, ~85 % Bildfüllung, TEMPORÄRER Rahmen ohne Moduswechsel), an die gemerkte Station zurückkehrt und beim Wegzoomen abbricht. **Liegen mehrere Neuzugänge, bleibt sie nach einer Wahl STEHEN** (die SERIE, 2026-09-01): der nächste rückt ins Fach nach, Kopfzeile und Info-Säule wechseln auf ihn — und weil `exchange_pending_die` die Indizes verrutschen läßt, ist der offene Neuzugang IMMER Index 0. Das Raster prüft seine Frische am INHALT (`DeckGlassView.pool_signature`), nicht an den Referenzen: der Tausch schreibt per `become` in die Instanz, die Liste bleibt gleich. Die Pool-Maschine kennt für das Raster eine ZWEITE Park-Konfiguration (tief, mit Schirm); die der RUNDE (flach, schirmlos) bleibt unberührt. Das Raster wohnt seit 2026-08-31 in einem EIGENEN, nicht-HDR-SubViewport mit `transparent_bg`: nur so trägt es echtes Per-Pixel-Alpha (der Helligkeits-Key und die Filz-Schwärzung sind damit gestorben), und seine Auflösung wird an der GEMESSENEN Bildschirm-Pixeldichte des Schirms bemessen statt am fernen Ausschnitt der einen Anzeige — gemessen 1,35 Texel/Pixel an der Pool-Station und 1,64 an der Werkstatt-Weitsicht (dort ist das Raster nur KLEINER: Netz-Zelle ~7,8 Bildschirm-px gegen ~11,7 am Pool, gemessen bei 1280 × 720). Siehe *Die GLAS-ANSICHT* in `scripts/ui/CLAUDE.md`.
- **Es gibt ZWEI PODESTE, und BEIDE stehen im Werkstatt-Streifen** (2026-09-04 — der FACH-SITZ als Podest ist gefallen, mit ihm `_fach_podium_target`, `PODIUM_HOVER`, `_bench_hover_for` und der ganze VORHANG des Ausgabefachs). Das LINKE ist das ZIEL-PODEST in der eigenen linken Spalte des Streifens (`WorkshopView.target_net_center()`/`target_projector_y()` → `scene_root._bench_podium_target`), das RECHTE das ERGEBNIS-PODEST (`result_net_center()`/`result_projector_y()`); beide schweben auf derselben `CLAMP_HOVER`, beide leeren Pucks schreibt der EINE `_seat_podium_puck`. Der TIPP auf einen VORRATS-Würfel wählt ihn als ZIEL der Serie (`WorkshopView.set_target_die` — derselbe wählt ab, ein anderer wechselt), und er fährt per **Bühnen-Fahrt** aus dem Pool auf das linke Podest; sein Pool-Sitz bleibt derweil LEER (`_bench_die` → `DiceTrayView.seat_shows`, die eine Sichtbarkeitsregel), und seine AUSKUNFT trägt das IST-NETZ darunter (Zeile 2 der Station). Das gilt an JEDER Station: `_wanted_bench_die()` fragt nur noch das Fenster, nicht mehr die Kamera — die Fahrt selbst wartet ohnehin auf den stehenden Vorrat. Rechtsklick wählt ab; ein Kamerawechsel NICHT (das Podest gehört dem Fenster, nicht der Station). Die **ÜBERGABE** wechselt den Würfel am Ende der Schablonen-Fahrt per HEBEBÜHNE die Seite — links versinkt der Körper, rechts steigt ein frisch gestellter (dieselbe Zwei-Bein-Grammatik wie Pool ↔ Bühne, EIN Körper), die Schablone faltet sich DORT in ihn, und der Soll-Schirm zeigt danach das ERGEBNIS mit grünen Deltas, bis ein anderes Ziel gewählt oder abgewählt wird. WO er steht, sagt `_bench_side` neben `_bench_die`; beide schreibt allein `_seat_bench_place`. Greifbar ist er auf beiden Seiten gleich, und der Rückweg in den Pool startet an der Seite, auf der er steht. Der EINE harte Abschluß der Übergabe ist `_settle_bench_handover_hard` (Skip mitten in der Fahrt), der EINE harte Aufräum-Pfad bleibt `_migrate_bench_to_pool`.
- **Der DOPPELKLICK auf den Podest-Würfel öffnet die INSPEKTION** (2026-09-01, an der Straße seit 2026-09-03 die einzige Nah-Geste): die Kamera fährt SUPER NAH heran — Rahmen = halbe Raumdiagonale mal `CameraRig.DIE_FOCUS_MARGIN`, gemessen ~7× näher als die Station —, der Würfel legt sich in die Dreiviertel-Ansicht (`die_focus_basis`, drei Seiten auf einmal), die Kamera steht STILL, und ein ZUG dreht IHN um die Bild-Achsen (`FloatingDie.spin`; ohne Fokus dreht derselbe Zug ihn an Ort). Es gibt **keinen Seiten-Pick** — hier wird gedreht und geschaut, nicht graviert. Sie ist **MODAL wie die Glas-Ansicht**: im Bild steht nur der Würfel, `_screen_forwards_pixel` schweigt, und WASD wie Doppelklick-Nahsicht sind taub. Wie die Glas-Ansicht ist es ein **TEMPORÄRER Rahmen**: `zoom_die_focus` meldet keinen Wechsel und rührt den Modus nicht an; die Lage davor merkt sich `scene_root._die_focus_home`. Rechtsklick und Rad-zurück gehen **EINE Stufe** aufs Podest zurück (`_leave_die_focus`), erst der nächste wählt ab — Fokus → Podest → Abwahl.
- **Das Bewegungs-Gesetz liest sich nach URHEBER**: was der *Spieler zahlt*, fliegt als KÖRPER im ballistischen Bogen (der WURF, `scene_root`s `#region Der WURF`); was der *Tisch liefert*, reist als LICHT über die gelegten Adern (die AUSNAHME seit der Korrektur-Welle I: Kassetten-Lieferungen ANS MAGAZIN fliegen als reiner METEOR-BOGEN ohne Ader, denn die Hub→Magazin-Ader ist gefallen; die Quell-Adern von Automat und Schwarzmarkt leben weiter); was er *präsentiert oder einzieht*, fährt per HEBEBÜHNE durch die Fläche. Kürzer gesagt (Welle O): **was der SPIELER bewegt, fliegt ÜBER dem Tisch; was der TISCH bewegt, fährt UNTER ihm** — MAGAZIN ⇄ SCHACHT ist ein Spieler-Zug und reist darum als TRAGE-BOGEN (`DataCellView.arc_to`, `scene_root._carry_data_cell`/`_return_data_cell`): sauber, ohne Trudeln, niedriger Bogen, kurzes Setzen. Unter dem Tisch bleiben die Lieferung ins Magazin, das Absinken der verbrauchten Karten nach dem Griff und die Bühnen-Fahrten der Würfel. Umgesetzt ist der Wurf bisher für den Nebenwetten-EINSATZ — Laden und Werkstatt zahlen noch Licht, ihr Umzug ist eine spätere Welle. Die ABLAGE eines benutzten Würfels ist dagegen ein EINZUG des Tisches und fährt darum per HEBEBÜHNE: eine würfelgroße Sektion öffnet unter seinem Liegeplatz in der Wurfgrube und senkt ihn ein (der SCHLUCK, `scene_root._swallow_dice`; der ballistische Ablage-Flug der Kuhle ist 2026-08-30 gestorben, siehe *Die WÜRFEL-BÜHNE* in `scripts/table/CLAUDE.md`). **Die eine benannte AUSNAHME ist die Wett-STEUER** (`scene_root._fly_bet_tax`): die Kleinsteuer je Hand ist kein Zahl-Moment, sondern ein Ticken, und sie reist darum als Meteor vom Schatz zum Wettfenster, wo der Bedingungs-Text kurz aufleuchtet. Neue Ausnahmen werden hier benannt oder es gibt sie nicht.
- **Die WERKSTATT ist eine SERIENSCHALTUNG** (2026-09-01): jede Gravur-Kassette trägt ein bei der Erzeugung gewürfeltes, überall SICHTBARES Prägenetz (`Pack.stamp_net`); SECHS Schächte stehen ab Runde 1 (Spieler-Entscheid 2026-09-04: die Hub-Leiter `SERIES_LADDER` ist auf EINE Sprosse geschrumpft, länger wird die Reihe nur noch über Taktgeber, Kettentreiber und Wett-Schub, Deckel 8); bis zu `series_slots()` Karten stecken in Reihenfolge, `SeriesResolver` summiert sie seitenweise (Operatoren wirken auf die aufgelaufene Summe — die REIHENFOLGE ist die Entscheidung), und EIN Griff je Sitzung projiziert alles auf EINEN spielergewählten Würfel, der per Bühnen-Fahrt aus dem Pool kommt. Presse-RNG, Multicast, Ablage, Platzier-Zweiklick und das Aufspannungs-Los sind tot; der Zufall wohnt im Laden-Angebot. Siehe *Die SERIENSCHALTUNG* in `scripts/ui/CLAUDE.md`.
- **Die WERKSTATT ist eine STATIONS-ZEILE UNTER dem Pool** (2026-09-04; sie zog von rechts neben dem Pool nach unten und wurde dabei vom Ausgabefach ENTKOPPELT): der Streifen hat **keinen Schirm** (`StyleBoxEmpty`, keine `window_*`-Uniforms im Glas) — seine Teile liegen auf dem Filz und lesen in **ZWEI ZEILEN plus Grube**: Zeile 1 ZIEL-PODEST | SCHACHT-REIHE | ERGEBNIS-PODEST, Zeile 2 — EIN durchgehendes BAND — IST-NETZ | SUMMEN-NETZ | SOLL-NETZ. Die beiden Podest-SPALTEN sind SPIEGELBILDER (`bench_column_rect()`/`result_column_rect()`, gleich breit, gleiche Fuge zur Reihe), damit liest der Streifen GANZ AUS SICH SELBST — er borgt sich weder Sitz noch Info-Säule mehr beim Ausgabefach, dessen Säule fortan NUR den Neuzugang zeigt. Die SCHACHT-REIHE ist je Serien-Slot ein KERF im erhabenen Konsolen-Blech: die ECHTE Data-Cell STEHT darin und steckt zu 82 % im Tisch (`seat_hard`, `SUNK_SHOW`) — nur Kappe und Lichtsaum stehen über dem Blech, und der Kerf ist der Fußabdruck der Kappe plus Luft — seit der Welle P HOCHKANT: gemessen 39,1 × 96,4 px bei einer Kappe von 35,9 × 88,5 px × `MOUTH_ROOM` 1,09. Die Reihe steht ab Runde 1 auf SECHS Kerfen. ALLE DREI Netze stehen auf BLANKEM FILZ, sind GLEICH GROSS (EIN Zellmaß, `WorkshopView.net_cell()` aus der engeren Spalte, gemessen 29,7 px) und **IMMER da**: ohne Inhalt als leeres Kreuz, nie versteckt. Links der Würfel WIE ER IST (`DieNetView`), rechts, was die Serie aus ihm macht (`PressNetView`, nach dem Griff mit grünen Deltas), MITTIG die REINE Summe aller gesteckten Prägenetze (zielunabhängig, `PressNetView.sum_net`) — und beim Hover über eine Karte (Schacht ODER Magazin) statt dessen DEREN Prägenetz. Darunter EINE Zeile (die CAPTION, `set_caption`): Zell-Klartext schlägt Kartenname, sonst leer; der dreizeilige Tooltip-Text ist TOT. Aufschlüsselungs-Zeilen und Augensumme sind es weiterhin. Der Summen-Schirm steht DIREKT UNTER der Schacht-Reihe und ist GENAU so breit wie sie. Das Konsolen-Band darunter trägt nur noch den GRIFF-Knopf (mittig unter der Reihe, Slot-Zähler in der Aufschrift: „Griff 2/4" = gesteckt/Serienlänge, während der Fahrt „Fertig"); der Serien-Schirm bleibt gestorben. Darunter das MAGAZIN über die volle Streifenbreite, unten bündig mit der Pool-Unterkante — es sei denn, die HOCHKANTE Karte braucht mehr Rang-Tiefe — sie tut es (gemessen: EIN Rang 105,4 px gegen 54,2 px Schürzenrest), also wächst der Streifen nach unten in den freien Filz. **`bench_rect()` streckt sich MIT — nach UNTEN bis zur ECHTEN Magazin-Unterkante**: genau so ein Überhang war in der Welle H der Bug „Upgrades lassen sich nicht wählen", weil die EINE Weiterleitungs-Region ihn nicht deckte; ein Test schickt darum einen Chip-Tap im unteren Grubenteil durch den ECHTEN Forward-Pfad. Das Fenster malt nur Münder, Netze und die beiden leeren Podest-Plätze und MELDET ihre Anker (`press_slot_anchors`/`press_display_anchors`, `target_net_center`/`target_projector_y`, `result_net_center`/`result_projector_y`, `ist_net_center` als Geburtsort der Schablone), die Körper gehören `scene_root`. `scene_root._fit_workshop_rect` legt den Streifen an: linke Kante bündig mit der POOL-REIHE, Oberkante eine Naht (`_pool_seam_px`, die halbe Slot-Teilung, um die die Pool-Reihe selbst gewachsen ist) unter ihr; Fenster PLUS Schürze (Naht + Band + Naht + Magazin) füllen zusammen die Pool-HÖHE, so daß die Magazin-Unterkante die Pool-Unterkante trifft (`scene_root` schiebt die gemessene Pool-Höhe als `apron_bottom` herein). Die BREITE wächst mit der Serienlänge (`bench_width_for` zählt Reihe plus Ränder plus ZWEIMAL Fuge und Podest-Spalte — vergißt man die zweite, läuft die Reihe über ihr Feld hinaus). Die Kamera (`configure_workshop_target`) rahmt allein Streifen und Magazin, OHNE Pool und OHNE Ausgabefach. Siehe *Die STATIONS-ZEILE* in `scripts/ui/CLAUDE.md`.

## Arbeitsweise (Spieler-Entscheidung 2026-08-25)
- **Delegiert wird nur bei echten FEATURE-WELLEN** (neue Mechanik, mehrere Subsysteme, Umbau einer Grammatik) — dann Plan-Datei + Opus-5-Subagent wie gehabt. **Kleine Änderungen macht die Session SELBST**: Ein-/Zwei-Datei-Fixes, Konstanten, Farben/Maße, visuelle Tweaks, Bugs mit bekannter Wurzel. Kein Plan-Dokument, kein Agenten-Aufsatz für so etwas.
- **Getestet wird EINMAL AM ENDE**, nicht nach jedem Schritt: ein Suiten-Pass, wenn die Änderung steht (plus Boot, falls `scene_root.gd` angefasst wurde). Kein Wiederholen der Läufe, die ein Subagent gerade grün gefahren hat — sein Log prüfen genügt (immer mit dem `Ignoring|Parse Error`-Grep, siehe unten); der eigene Vollpass gehört vor den Commit.
